Quote verification is the single highest-value guardrail. Hallucinated citations are the #1 failure mode of "AI evaluator" demos:
python

import re

def _norm(s: str) -> str:
    return re.sub(r"\s+", " ", s).strip().lower()

def verify_evidence(score: CriterionScore, chunks) -> CriterionScore:
    text_by_doc = {c.doc_id: _norm(c.text) for c in chunks}
    kept = []
    for ev in score.evidence:
        source = text_by_doc.get(ev.doc_id, "")
        if _norm(ev.quote) and _norm(ev.quote) in source:
            kept.append(ev)
        else:
            score.missing_info.append(f"unverified quote: {ev.quote[:60]}")
    if len(kept) < len(score.evidence):
        score.confidence = "low"
    score.evidence = kept
    return score

def aggregate(scores: dict[str, CriterionScore], rubric) -> dict:
    # 1. gates first — a failed gate is disqualifying, not a deduction
    gate_results = evaluate_gates(rubric.gates, scores)
    if not all(gate_results.values()):
        return {"status": "non_compliant", "gates": gate_results}

    # 2. weighted score over scored criteria only
    scored = [c for c in rubric.criteria if c.type == "scored"]
    total_w = sum(c.weight for c in scored)
    raw = sum(scores[c.id].score * c.weight for c in scored) / total_w
    return {
        "status": "evaluated",
        "weighted_score": round(raw, 2),
        "gates": gate_results,
        "low_confidence": [c.id for c in scored
                           if scores[c.id].confidence == "low"],
    }

7. The part everyone skips: measuring the evaluator

Before anyone trusts this on real tenders, build a golden set: 30–50 past bids with human scores from completed evaluations. Then track, per criterion:

    MAE / RMSE between AI proposal and human score

    Spearman correlation with human ranking (ranking matters more than absolute scores)

    Weighted Cohen's kappa for pass/fail gates

    Override rate per criterion — high override rate = that criterion's prompt or rubric is broken

Ship a criterion only when it beats a threshold you set (e.g. override rate < 20%). This is exactly what separates a usable system from a demo, and it's where most of your engineering time will go.

4. The BQ — do it deterministically

Bills of quantities are the highest-volume, most error-prone part, and the one place AI scoring is actively harmful. Parse to rows, then verify with plain code.
python

class BQRow(BaseModel):
    item: str
    description: str
    unit: str
    qty: float
    rate: float
    amount: float

def check_bq(rows: list[BQRow], tolerance=0.01) -> dict:
    issues = []
    for r in rows:
        expected = round(r.qty * r.rate, 2)
        if abs(expected - r.amount) > tolerance:
            issues.append({"item": r.item, "type": "extension_error",
                           "expected": expected, "stated": r.amount})
    stated_total = sum(r.amount for r in rows)
    return {"total": stated_total, "issues": issues,
            "issue_count": len(issues), "rows": len(rows)}

What this catches, every time, with zero hallucination risk:

    Extension errors (qty × rate ≠ amount) — surprisingly common.

    Summation errors (line items don't add to the stated total).

    Omitted items (bidder's BQ missing rows present in the tender BQ) — set difference on item codes.

    Unit mismatches (rate per m² quoted against a per-m³ item).

    Provisional sums / dayworks treated inconsistently across bidders.

Store the parsed BQ in a normalised table, keyed (bid_id, item_code). Everything downstream (ALT detection, comparison views) reads from there.
5. Abnormally low tender (ALT) detection

import numpy as np

def flag_abnormal_rates(rate_matrix: dict[str, dict[str, float]],
                        floor_pct=0.70, iqr_k=1.5) -> list[dict]:
    """
    rate_matrix: {bidder_id: {item_code: rate}}
    Flags a bidder/item when the rate is far below the peer distribution.
    """
    items = {i for b in rate_matrix.values() for i in b}
    flags = []
    for item in items:
        rates = {b: m[item] for b, m in rate_matrix.items() if item in m}
        if len(rates) < 4:                       # too few bidders to judge
            continue
        vals = np.array(list(rates.values()))
        median = float(np.median(vals))
        q1, q3 = np.percentile(vals, [25, 75])
        iqr = q3 - q1
        for bidder, r in rates.items():
            if r < median * floor_pct or (iqr > 0 and r < q1 - iqr_k * iqr):
                flags.append({"bidder": bidder, "item": item, "rate": r,
                              "median": median,
                              "pct_of_median": round(r / median, 3)})
    return flags

Feed the flags into the human workflow — ALT is a query to the bidder, not an automatic disqualification, and the rules differ by jurisdiction. Surface it as "items to clarify," never as a score deduction.

7. Two-envelope discipline in the architecture

    Separate Postgres schemas for technical and commercial envelopes; separate vector collections.

A.3 Dedup and canonicalisation — the step that saves the evaluator's sanity

Specs repeat requirements across divisions ("submit method statements" appears in five sections). PSSCOC has overlapping clauses. If you don't dedup, the compliance matrix has 1,400 rows and the evaluator closes the tab.
python

from rapidfuzz import fuzz
import hashlib

def canonical_id(req) -> str:
    # normalise: lowercase, strip refs, collapse quantities to placeholders
    t = req.requirement_text.lower()
    t = re.sub(r"\d+(\.\d+)?", "#", t)
    t = re.sub(r"\b(clause|section|ref)\s*[\d\.]+", "", t)
    return hashlib.sha1(t.encode()).hexdigest()[:12]

def dedup(requirements, embed_fn, sim_threshold=0.92):
    clusters = {}
    for r in requirements:
        key = canonical_id(r)
        if key in clusters:
            clusters[key].append(r); continue
        # second pass: semantic near-dup
        matched = None
        for k, members in clusters.items():
            if r.category != members[0].category:      # never merge across categories
                continue
            if fuzz.token_set_ratio(r.requirement_text,
                                    members[0].requirement_text) > sim_threshold * 100:
                matched = k; break
        if matched:
            clusters[matched].append(r)
        else:
            clusters[key] = [r]

    merged = []
    for members in clusters.values():
        primary = members[0]
        primary.cross_refs = sorted({c for m in members for c in [m.clause_ref] + m.cross_refs})
        primary.source_quote = " || ".join(m.source_quote for m in members)
        merged.append(primary)
    return merged

Two rules: never merge across category (a submission requirement and a technical requirement can read similarly), and always keep every clause_ref in cross_refs so the matrix can cite all locations.

Typical effect: 900 raw extractions → 350–450 canonical requirements. That's a matrix an evaluator will actually read.
A.4 Taxonomy hygiene and edge cases

    Conditional requirements get a condition field that the resolver must evaluate first. "If the contract value exceeds S$5m, submit a performance bond" — a small bidder that doesn't need a bond is not non-compliant.

    Employer obligations must be excluded (prompt 1a handles this, but audit the output — the model will occasionally flag "The Employer shall pay within 30 days" because it matches the shall-pattern).

    Drawings register / appendices: extract as document requirements (submission of as-builts, O&M manuals), but do not attempt to extract requirements from drawings in phase 1.

    Standards incorporation: "in accordance with SS 553" is a requirement; the standard itself is external. Record it as cross_refs: ["SS 553"] and flag verification_type: qualitative — don't try to fetch the standard.

Part B — The compliance resolver
B.1 Why the obvious approach fails

The naïve design — "for each requirement, semantic-search the bid, ask the LLM" — fails in three specific, reproducible ways:

    False negatives on absence. Semantic retrieval always returns something top-k. The model then rationalises a weak chunk as compliance. You report "compliant" for a requirement the bidder ignored. This is the catastrophic failure mode — missed non-compliance is what gets the evaluation challenged.

    Cross-reference blindness. Bidder writes "Key personnel: refer Section 3.4." Retrieval returns Section 3.4 but not the link. Model says "not addressed" because it never saw the connection.

    Inconsistency across bidders. Bidder A's methodology is prose, Bidder B's is a table. Different retrieval shapes → different scores → indefensible.

The design below addresses all three: navigate-then-extract for problem 1, explicit cross-ref resolution for problem 2, fixed context structure for problem 3.

B.3 Navigate-then-extract — the two-stage protocol

Stage 1: navigation. Ask a cheap model, per requirement, where in this bid would the answer be, if it exists? Give it the TOC and the requirement. It returns candidate sections. This catches requirements whose answer lives in a section the embedding model didn't rank highly (e.g. "confined space procedure" answered in a WSH appendix, not the methodology chapter).

Stage 2: extraction. Fetch the navigated sections plus the top retrieval hits plus the clause-echo hits. Union, dedup, cap at ~6,000 tokens. Then run the resolver prompt over this fixed-structure context.

{retrieval_sections}

=== DECISION RULES — follow exactly ===

1. CONDITION FIRST. If conditional=true, evaluate the condition before the
   requirement. If the condition is not triggered by this bid, return
   status="not_applicable" and explain. Do not assess the requirement itself.

2. STATUS DEFINITIONS — apply strictly:
   - compliant: every element of the requirement is demonstrably met, with
     direct evidence. Partial coverage is NOT compliant.
   - partial: the bidder addresses the requirement but omits a stated element
     (a missing certificate, a sub-component, a threshold not quantified).
   - non_compliant: the bidder addresses the requirement but fails it (wrong
     value, expired document, insufficient quantity, wrong standard).
   - not_addressed: after reviewing ALL provided excerpts, nothing in the
     submission responds to this requirement.
   - not_applicable: condition not triggered, or requirement does not apply.

3. EVIDENCE IS VERBATIM. Every quote must be copied exactly from an excerpt,
   including the doc_id and page. Do not paraphrase. Do not synthesise a quote
   from multiple fragments.

4. ABSENCE PROTOCOL — the most important rule:
   - Before returning not_addressed, you MUST review every excerpt provided,
     including [ECHO] and [NAV].
   - For not_addressed, gap_note must state what you looked for and where
     you looked: "Reviewed Methodology (p.12-18), WSH Plan (p.34-40), and
     Personnel Schedule (p.22); none address [specific requirement element]."
   - If an excerpt is truncated mid-sentence, or the TOC indicates a section
     that was not provided, return status="partial" with evaluator_flag=
     "needs_clarification" and state which section must be reviewed — do NOT
     return not_addressed on incomplete information.

5. CROSS-REFERENCES. If an excerpt says "refer Section X" or "as per our
   methodology", and Section X is provided, assess using Section X's content.
   List resolved references in cross_ref_resolved. If the referenced section
   is NOT provided, return evaluator_flag="needs_clarification".

6. NEVER infer compliance from silence, from the bidder's general
   capabilities, or from a different requirement that happens to be similar.
   If the exact element is not present, it is not present.

7. QUANTITIES. If the requirement specifies a threshold (amount, years,
   duration, count), compare it explicitly against the bidder's stated value.
   State both numbers in gap_note when returning non_compliant.

Three design choices worth defending:

    not_addressed vs non_compliant are separated. They have different consequences (one is a query to the bidder, one may be disqualifying) and conflating them forces the evaluator to re-read every gap.

    The absence protocol forces enumeration. The model must name the sections it checked. This makes false "not_addressed" visible — the evaluator sees the model checked p.12–18 but not the appendix, and flags it.

    evaluator_flag is a pressure valve. Ambiguous requirements and truncated context get surfaced, not guessed. This is how you keep override rates low: the model isn't forced into a wrong answer.

def verify_and_sanitise(row: ComplianceRow, excerpts: list[Excerpt]) -> ComplianceRow:
    text_by_loc = {(e.doc_id, e.page): _norm(e.text) for e in excerpts}

    verified = []
    for ev in row.evidence:
        src = text_by_loc.get((ev.doc_id, ev.page), "")
        if _norm(ev.quote) and _norm(ev.quote) in src:
            verified.append(ev)
        else:
            row.evaluator_flag = "needs_clarification"
    row.evidence = verified

    # status sanity
    if row.status in ("compliant", "partial", "non_compliant") and not row.evidence:
        row.status = "not_addressed"
        row.evaluator_flag = "needs_clarification"
        row.confidence = "low"

    if row.status == "not_addressed" and not row.gap_note:
        row.confidence = "low"      # absence with no enumeration = untrustworthy

    if row.status == "compliant" and row.confidence == "low":
        row.evaluator_flag = "needs_clarification"

    return row

Rule: a status with no verified quote cannot be compliant, partial, or non_compliant. This single check eliminates the majority of hallucinated compliance.
B.5 Consistency across bidders

    Identical context structure for every bidder on a given requirement: same excerpt slots, same order (ECHO → NAV → RETRIEVAL), same cap. If Bidder A gets 4 retrieval chunks and Bidder B gets 8, their scores are not comparable.

2. Sealing (Merkle tree + signature)

import hashlib
import json
from dataclasses import dataclass
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
import base64

def _h(b: bytes) -> str:
    return hashlib.sha256(b).hexdigest()

def canonical(row) -> bytes:
    return json.dumps(row, sort_keys=True, separators=(",", ":")).encode()

def merkle_root(leaves: list[bytes]) -> str:
    if not leaves:
        return _h(b"")
    layer = [_h(l) for l in leaves]
    while len(layer) > 1:
        nxt = []
        for i in range(0, len(layer), 2):
            a = layer[i]
            b = layer[i+1] if i+1 < len(layer) else a
            nxt.append(_h((a+b).encode()))
        layer = nxt
    return layer[0]

@dataclass
class Seal:
    tender_id: str
    envelope: str
    merkle_root: str
    leaf_count: int
    signature: str
    signed_at: str

def seal_envelope(rows: list[dict], tender_id: str, envelope: str,
                  signer: Ed25519PrivateKey) -> Seal:
    leaves = [canonical({k: r[k] for k in sorted(r) if r[k] is not None})
              for r in rows]
    root = merkle_root(leaves)
    payload = f"{tender_id}|{envelope}|{root}|{len(leaves)}".encode()
    sig = signer.sign(payload)
    return Seal(
        tender_id=tender_id,
        envelope=envelope,
        merkle_root=root,
        leaf_count=len(leaves),
        signature=base64.b64encode(sig).decode(),
        signed_at=_utcnow_iso(),
    )

class Claims(BaseModel):
    sub: str            # user id
    email: str
    role: str

    return jwt.encode(claims.model_dump(), secret, algorithm="HS256")

def verify(token: str, secret: str) -> Claims:
    try:
        payload = jwt.decode(token, secret, algorithms=["HS256"])
        return Claims(**payload)
    except JWTError as e:
        raise AuthError("invalid token") from e

    async def _dep(user: Claims = Depends(current_user),
                   tender_id: str = None) -> Claims:   # tender_id from path
        role = Role(user.role)
        if envelope not in READ_POLICY[role]:
            raise HTTPException(403, f"role {role.value} cannot read {envelope}")
        # lead is locked to one envelope per session
        if role == Role.EVALUATION_LEAD:
            if user.envelope_scope != envelope:
                raise HTTPException(423,
                    f"lead session is locked to {user.envelope_scope or 'none'}; "
                    f"re-auth with envelope_scope={envelope} to switch")
        # commercial read requires technical seal — the hard lock
        if envelope == "commercial":
            if not await _envelope_sealed(tender_id, "technical"):
                raise HTTPException(423,
                    "technical envelope not sealed; commercial is locked")
        return user
    return _dep

def require_write(envelope: str):
    async def _dep(user: Claims = Depends(current_user),
                   tender_id: str = None) -> Claims:
        role = Role(user.role)
        if envelope not in WRITE_POLICY[role]:
            raise HTTPException(403, f"role {role.value} cannot write {envelope}")
        # sealed envelopes reject writes at the API layer, DB layer enforces too (§3.3)
        if await _envelope_sealed(tender_id, envelope):
            raise HTTPException(423, f"{envelope} envelope is sealed")
        return user
    return _dep

2.4 The lead's "one envelope per session" rule

EVALUATION_LEAD needs both envelopes eventually, but never simultaneously. The envelope_scope claim enforces this:

    Lead logs in → envelope_scope = "technical" (or none, then chooses on first access).

    If they try to hit a /commercial/* endpoint with a technical scope, they get 423.

    To switch, they re-authenticate (with step-up MFA) and receive a new token with envelope_scope = "commercial".

3.1 Canonicalisation + Merkle + signature

# app/sealing/merkle.py
import hashlib, json
from dataclasses import dataclass, asdict
from datetime import datetime, timezone
from cryptography.hazmat.primitives.asymmetric.ed25519 import (
    Ed25519PrivateKey, Ed25519PublicKey)
import base64

def _sha(b: bytes) -> str:
    return hashlib.sha256(b).hexdigest()

def canonical_row(row: dict) -> bytes:
    """Deterministic JSON: sorted keys, no whitespace, no None."""
    clean = {k: v for k, v in sorted(row.items()) if v is not None}
    return json.dumps(clean, sort_keys=True, separators=(",", ":"),
                      default=str).encode()

def merkle_root(leaves: list[bytes]) -> str:
    if not leaves:
        return _sha(b"")
    layer = [_sha(l) for l in leaves]
    while len(layer) > 1:
        nxt = []
        for i in range(0, len(layer), 2):
            a = layer[i]
            b = layer[i+1] if i + 1 < len(layer) else a
            nxt.append(_sha((a + b).encode()))
        layer = nxt
    return layer[0]

@dataclass
class SealedPayload:
    tender_id: str
    envelope: str
    merkle_root: str
    leaf_count: int
    prev_seal_id: str | None
    signed_at: str
    signature: str
    signer_key_id: str

def sign_seal(rows: list[dict], tender_id: str, envelope: str,
              prev_seal_id: str | None, signer_key_id: str,
              key: Ed25519PrivateKey) -> SealedPayload:
    leaves = [canonical_row(r) for r in rows]
    root = merkle_root(leaves)
    signed_at = datetime.now(timezone.utc).isoformat()
    message = f"{tender_id}|{envelope}|{root}|{len(leaves)}|{prev_seal_id or ''}".encode()
    sig = key.sign(message)
    return SealedPayload(
        tender_id=tender_id, envelope=envelope,
        merkle_root=root, leaf_count=len(leaves),
        prev_seal_id=prev_seal_id, signed_at=signed_at,
        signature=base64.b64encode(sig).decode(),
        signer_key_id=signer_key_id,
    )

def verify_seal(payload: SealedPayload, snapshot: list[dict],
                pubkey: Ed25519PublicKey) -> bool:
    leaves = [canonical_row(r) for r in snapshot]
    if merkle_root(leaves) != payload.merkle_root:
        return False
    message = (f"{payload.tender_id}|{payload.envelope}|{payload.merkle_root}|"
               f"{payload.leaf_count}|{payload.prev_seal_id or ''}").encode()
    try:
        pubkey.verify(base64.b64decode(payload.signature), message)
        return True
    except Exception:
        return False

Key management: the Ed25519 private key lives in your KMS/HSM, never on the API box. The sign_seal call above is the logical interface; in production it's wrapped by a KMS Sign call. The signature covers prev_seal_id, which chains seals — tampering with a historical seal invalidates every subsequent one.

               signature, signer_key_id, signed_by, signed_at, prev_seal_id)
            VALUES ($1,$2,$3,$4,$5::jsonb,$6,$7,$8,$9,$10)
            RETURNING id
        """, tender_id, envelope, sealed.merkle_root, sealed.leaf_count,
             json.dumps(snapshot), sealed.signature, sealed.signer_key_id,
             user.sub, sealed.signed_at,
             sealed.prev_seal_id)
        await tx.execute("""
            UPDATE core.tenders
            SET state = CASE
                WHEN $2 = 'technical' THEN 'tech_sealed'
                WHEN $2 = 'commercial' THEN 'commercial_sealed'
            END
            WHERE id = $1
        """, tender_id, envelope)
        await append_audit(tx, tender_id, envelope, user.sub, "seal",
                           f"{schema}.seals", seal_id,
                           None, asdict(sealed))

3.3 Database-level write rejection

Application code can be bypassed by a bug; add a trigger that rejects writes to sealed data:
sql

CREATE OR REPLACE FUNCTION technical.reject_sealed_writes() RETURNS trigger AS $$
DECLARE
  sealed BOOLEAN;
BEGIN
  SELECT EXISTS (
    SELECT 1 FROM technical.seals
    WHERE tender_id = COALESCE(NEW.tender_id, OLD.tender_id)
      AND revoked_at IS NULL
  ) INTO sealed;
  IF sealed THEN
    RAISE EXCEPTION 'technical envelope is sealed; no writes permitted';
  END IF;
  RETURN COALESCE(NEW, OLD);
END; $$ LANGUAGE plpgsql;

CREATE TRIGGER technical_no_write_when_sealed
  BEFORE INSERT OR UPDATE OR DELETE ON technical.compliance_rows
  FOR EACH ROW EXECUTE FUNCTION technical.reject_sealed_writes();

import hashlib, json

GENESIS = "0" * 64

async def append_audit(tx, tender_id, envelope, actor,
                       action, target_table, target_id,
                       before, after):
    prev = await tx.fetchval("""
        SELECT hash FROM audit.ledger
        WHERE tender_id = $1
        ORDER BY ts DESC, id DESC LIMIT 1
    """, tender_id) or GENESIS

    payload = {
        "tender_id": str(tender_id),
        "envelope": envelope,
        "actor": str(actor) if actor else None,
        "action": action,
        "target_table": target_table,
        "target_id": str(target_id) if target_id else None,
        "before": before,
        "after": after,
        "prev_hash": prev,
    }
    h = hashlib.sha256(
        json.dumps(payload, sort_keys=True, separators=(",", ":"),
                   default=str).encode()
    ).hexdigest()
    await tx.execute("""
        INSERT INTO audit.ledger
          (tender_id, envelope, actor, action, target_table, target_id,
           before, after, prev_hash, hash)
        VALUES ($1,$2,$3,$4,$5,$6,$7::jsonb,$8::jsonb,$9,$10)
    """, tender_id, envelope, actor, action, target_table, target_id,
         json.dumps(before, default=str) if before else None,
         json.dumps(after, default=str) if after else None,
         prev, h)
    return h

# app/audit/verify.py
async def verify_chain(tender_id: str) -> dict:
    rows = await db.fetch("""
        SELECT id, ts, envelope, actor, action, target_table, target_id,
               before, after, prev_hash, hash
        FROM audit.ledger
        WHERE tender_id = $1
        ORDER BY ts, id
    """, tender_id)
    prev = GENESIS
    for r in rows:
        payload = {
            "tender_id": tender_id,
            "envelope": r["envelope"],
            "actor": str(r["actor"]) if r["actor"] else None,
            "action": r["action"],
            "target_table": r["target_table"],
            "target_id": str(r["target_id"]) if r["target_id"] else None,
            "before": r["before"],
            "after": r["after"],
            "prev_hash": r["prev_hash"],
        }
        expected = hashlib.sha256(
            json.dumps(payload, sort_keys=True, separators=(",", ":"),
                       default=str).encode()
        ).hexdigest()
        if r["prev_hash"] != prev:
            return {"ok": False, "reason": "prev_hash mismatch",
                    "at": str(r["id"]), "ts": r["ts"].isoformat()}
        if expected != r["hash"]:
            return {"ok": False, "reason": "hash mismatch",
                    "at": str(r["id"]), "ts": r["ts"].isoformat()}
        prev = r["hash"]
    return {"ok": True, "entries": len(rows), "head": prev}

class OverrideBody(BaseModel):
    status: str
    note: str | None = None
    reason: str                     # required — must be non-empty
    expected_version: str           # the ai_proposed_at timestamp; optimistic lock

@router.post("/tenders/{tender_id}/{envelope}/rows/{row_id}/override")
async def override_row(
    tender_id: str, envelope: str, row_id: str,
    body: OverrideBody,
    user: Claims = Depends(current_user),
):
    await require_write(envelope)(user, tender_id)
    async with db.transaction() as tx:
        before = await tx.fetchrow(f"""
            SELECT * FROM {envelope}.compliance_rows
            WHERE id = $1 AND tender_id = $2 FOR UPDATE
        """, row_id, tender_id)
        if not before:
            raise HTTPException(404)
        # optimistic lock — prevents two evaluators racing
        if str(before["ai_proposed_at"]) != body.expected_version:
            raise HTTPException(409, "row was updated by another session; reload")
        await tx.execute(f"""
            UPDATE {envelope}.compliance_rows
            SET human_status = $1, human_note = $2, override_reason = $3,
                human_actor = $4, human_decided_at = now()
            WHERE id = $5
        """, body.status, body.note, body.reason, user.sub, row_id)
        after = dict(before)
        after["human_status"] = body.status
        after["override_reason"] = body.reason
        await append_audit(tx, tender_id, envelope, user.sub, "override",
                           f"{envelope}.compliance_rows", row_id,
                           _jsonable(dict(before)), _jsonable(after))
    return {"ok": True}

def _jsonable(d: dict) -> dict:
    return {k: (str(v) if hasattr(v, "isoformat") else v)
            for k, v in d.items()}

A.2 Award schema, role, and the only path to cross-envelope data

The award service is the only component that reads both envelopes — and only after both seals exist. Enforce this at the database layer so a bug in the award service cannot bypass it.
sql

CREATE SCHEMA IF NOT EXISTS award;

-- The award service role can ONLY call this function. No direct table access.
CREATE ROLE award_role;
GRANT USAGE ON SCHEMA award TO award_role;

-- Return type is the union of both envelopes in a single, structured shape.
CREATE TYPE award.bidder_package AS (
  bidder_id         UUID,
  bidder_name       TEXT,
  -- technical
  compliance        JSONB,           -- [{clause_ref, mandatory, human_status, evidence}]
  criterion_scores  JSONB,           -- [{code, weight, human_score}]
  gates_passed      BOOLEAN,
  -- commercial
  bq_issues         JSONB,
  alt_flags         JSONB,
  evaluated_price   NUMERIC
);

-- SECURITY DEFINER function: runs as owner, checks both seals itself.
-- award_role does not need direct SELECT on technical.* or commercial.*.
CREATE OR REPLACE FUNCTION award.read_after_both_sealed(p_tender_id UUID)
RETURNS SETOF award.bidder_package
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = award, pg_catalog
AS $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM technical.seals
    WHERE tender_id = p_tender_id AND revoked_at IS NULL
  ) THEN
    RAISE EXCEPTION 'technical envelope not sealed for tender %', p_tender_id
      USING ERRCODE = '42501';
  END IF;
  IF NOT EXISTS (
    SELECT 1 FROM commercial.seals
    WHERE tender_id = p_tender_id AND revoked_at IS NULL
  ) THEN
    RAISE EXCEPTION 'commercial envelope not sealed for tender %', p_tender_id
      USING ERRCODE = '42501';
  END IF;

  RETURN QUERY
  SELECT
    b.id,
    b.name,
    -- compliance
    COALESCE(
      (SELECT jsonb_agg(jsonb_build_object(
                'clause_ref', r.clause_ref,
                'mandatory',  r.mandatory,
                'status',     COALESCE(cr.human_status, cr.ai_status),
                'evidence',   cr.ai_evidence,
                'gap_note',   cr.ai_gap_note))
         FROM technical.compliance_rows cr
         JOIN core.requirements r ON r.id = cr.requirement_id
        WHERE cr.bidder_id = b.id AND cr.tender_id = p_tender_id),
      '[]'::jsonb),
    -- criterion scores
    COALESCE(
      (SELECT jsonb_agg(jsonb_build_object(
                'code',         rc.code,
                'weight',       rc.weight,
                'human_score',  cs.human_score,
                'ai_score',     cs.ai_score))
         FROM technical.criterion_scores cs
         JOIN core.rubric_criteria rc ON rc.id = cs.criterion_id
        WHERE cs.bidder_id = b.id
          AND cs.tender_id = p_tender_id
          AND rc.envelope = 'technical'),
      '[]'::jsonb),
    -- gates
    NOT EXISTS (
      SELECT 1 FROM technical.compliance_rows cr2
      JOIN core.requirements r2 ON r2.id = cr2.requirement_id
      WHERE cr2.bidder_id = b.id
        AND cr2.tender_id = p_tender_id
        AND r2.mandatory
        AND r2.category = 'gate'
        AND COALESCE(cr2.human_status, cr2.ai_status)
            IN ('non_compliant','not_addressed')
    ),
    -- commercial
    COALESCE(
      (SELECT jsonb_agg(jsonb_build_object(
                'issue_type', issue_type,
                'item_code',  item_code,
                'detail',     detail))
         FROM commercial.bq_checks
        WHERE bidder_id = b.id AND tender_id = p_tender_id),
      '[]'::jsonb),
    COALESCE(
      (SELECT jsonb_agg(jsonb_build_object(
                'item_code', item_code,
                'rate',      rate,
                'median',    median_rate,
                'pct',       pct_of_median))
         FROM commercial.alt_flags
        WHERE bidder_id = b.id AND tender_id = p_tender_id),
      '[]'::jsonb),
    -- evaluated_price — the gross submitted price, from the BQ total row
    (SELECT (detail->>'total')::numeric
       FROM commercial.bq_checks
      WHERE bidder_id = b.id
        AND tender_id = p_tender_id
        AND issue_type = 'total'
      LIMIT 1)
  FROM core.bidders b
  WHERE b.tender_id = p_tender_id;
END;
$$;

REVOKE ALL ON FUNCTION award.read_after_both_sealed(UUID) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION award.read_after_both_sealed(UUID) TO award_role;

Why a SECURITY DEFINER function? Because the award service role has zero direct access to either envelope. Even a compromised award service cannot query technical.compliance_rows — it can only call this function, which refuses to run unless both seals exist. That's a property you can demonstrate to an auditor with a single SQL statement: \df+ award.read_after_both_sealed shows the guard.
A.3 Award formulas

Three formulas cover almost all public construction procurement. Each is selected per-tender via core.rubric_criteria metadata, and all are pure functions over the sealed data — no AI, no free-text.
python

# award/formulas.py
from dataclasses import dataclass
from decimal import Decimal, ROUND_HALF_UP

@dataclass
class BidderResult:
    bidder_id: str
    bidder_name: str
    passed_gates: bool
    compliance_summary: dict        # {'non_compliant': n, 'not_addressed': n, ...}
    technical_score: Decimal        # weighted 0..scale_max
    evaluated_price: Decimal | None
    fee_score: Decimal | None       # 0..100
    final_score: Decimal | None
    rank: int | None
    ineligible_reason: str | None

def _d(x) -> Decimal:
    return Decimal(str(x)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

# ── Lowest Compliant Price ──────────────────────────────────────────
# Eligible = passed gates AND no disqualifying non-compliance on mandatory reqs
# Winner = lowest evaluated_price among eligible
def lcp(packages: list[dict], config: dict) -> list[BidderResult]:
    results = [_base_result(p) for p in packages]
    eligible = [r for r in results if r.passed_gates and r.ineligible_reason is None
                and r.evaluated_price is not None]
    if not eligible:
        return results
    winner = min(eligible, key=lambda r: r.evaluated_price)
    for i, r in enumerate(sorted(eligible, key=lambda r: r.evaluated_price), 1):
        r.rank = i
        r.final_score = r.evaluated_price
    winner.rank = 1
    return results

# ── Quality-Fee Method (Singapore MOF style) ────────────────────────
# Q = technical score normalised to 0..100
# F = 100 * (lowest_fee / bidder_fee)    [inverse linear, floor 0]
# Final = w_q * Q + w_f * F              [weights sum to 1, e.g. 0.7 / 0.3]
# Winner = highest Final
def qfm(packages: list[dict], config: dict) -> list[BidderResult]:
    w_q = Decimal(str(config.get("quality_weight", "0.7")))
    w_f = Decimal("1") - w_q
    scale_max = Decimal(str(config.get("scale_max", "100")))

    results = [_base_result(p) for p in packages]
    eligible = [r for r in results if r.passed_gates and r.ineligible_reason is None
                and r.evaluated_price and r.evaluated_price > 0]
    if not eligible:
        return results

    lowest_fee = min(r.evaluated_price for r in eligible)
    for r in eligible:
        r.fee_score = _d(Decimal("100") * lowest_fee / r.evaluated_price)
        q_norm = _d(r.technical_score * Decimal("100") / scale_max)
        r.final_score = _d(w_q * q_norm + w_f * r.fee_score)

    for i, r in enumerate(sorted(eligible, key=lambda r: r.final_score, reverse=True), 1):
        r.rank = i
    return results

# ── Price-Quality Method (weighted normalised) ──────────────────────
# score = w_q * (Q / Q_ref) + w_p * (P_min / P)
# Q_ref = configurable (either "observed_max" or an absolute reference)
# Winner = highest score
def pqm(packages: list[dict], config: dict) -> list[BidderResult]:
    w_q = Decimal(str(config.get("quality_weight", "0.6")))
    w_p = Decimal("1") - w_q
    q_ref_mode = config.get("quality_reference", "observed_max")

    results = [_base_result(p) for p in packages]
    eligible = [r for r in results if r.passed_gates and r.ineligible_reason is None
                and r.evaluated_price and r.evaluated_price > 0]
    if not eligible:
        return results

    if q_ref_mode == "observed_max":
        q_ref = max(r.technical_score for r in eligible) or Decimal("1")
    else:
        q_ref = Decimal(str(config.get("quality_reference_value", "100")))

    p_min = min(r.evaluated_price for r in eligible)
    for r in eligible:
        q_norm = r.technical_score / q_ref if q_ref > 0 else Decimal("0")
        p_norm = p_min / r.evaluated_price
        r.final_score = _d(w_q * q_norm + w_p * p_norm)
        r.fee_score = None

    for i, r in enumerate(sorted(eligible, key=lambda r: r.final_score, reverse=True), 1):
        r.rank = i
    return results

# ── shared helpers ──────────────────────────────────────────────────
def _base_result(package: dict) -> BidderResult:
    comp = package["compliance"] or []
    summary = {"compliant": 0, "partial": 0, "non_compliant": 0,
               "not_addressed": 0, "not_applicable": 0}
    for row in comp:
        summary[row["status"]] = summary.get(row["status"], 0) + 1

    # disqualifying = any mandatory non_compliant (not partial, not not_addressed)
    # partial/not_addressed on mandatory → "query to bidder", not automatic DQ
    # (adjust to your procurement rules; some codes auto-DQ on not_addressed)
    dq = any(
        row["mandatory"] and row["status"] == "non_compliant"
        for row in comp
    )
    tech = Decimal("0")
    scores = package["criterion_scores"] or []
    total_w = sum((Decimal(str(c["weight"])) for c in scores), Decimal("0"))
    if total_w > 0:
        tech = sum(
            (Decimal(str(c["human_score"] or 0)) * Decimal(str(c["weight"]))
             for c in scores), Decimal("0")
        ) / total_w

    return BidderResult(
        bidder_id=package["bidder_id"],
        bidder_name=package["bidder_name"],
        passed_gates=package["gates_passed"],
        compliance_summary=summary,
        technical_score=_d(tech),
        evaluated_price=(_d(package["evaluated_price"])
                         if package["evaluated_price"] is not None else None),
        fee_score=None,
        final_score=None,
        rank=None,
        ineligible_reason=("failed_gates" if not package["gates_passed"]
                          else "disqualifying_non_compliance" if dq
                          else None),
    )

FORMULAS = {"lcp": lcp, "qfm": qfm, "pqm": pqm}

The choice of formula is per-tender and stored in core.award_config:
sql

CREATE TABLE award.config (
  tender_id     UUID PRIMARY KEY REFERENCES core.tenders(id) ON DELETE CASCADE,
  formula       TEXT NOT NULL CHECK (formula IN ('lcp','qfm','pqm')),
  params        JSONB NOT NULL DEFAULT '{}',
  frozen_at     TIMESTAMPTZ,           -- set when the tender is published; cannot change after
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

frozen_at prevents the formula being changed after bids are in — a documented risk in procurement.
A.4 Award computation pipeline

The award service is a separate deployment with its own credentials. It runs only when triggered by the procurement officer, and only after both seals exist.
python

# award/service.py
import json, hashlib
from datetime import datetime, timezone
from decimal import Decimal

def _jsonable(obj):
    if isinstance(obj, Decimal):  return str(obj)
    if isinstance(obj, datetime): return obj.isoformat()
    raise TypeError

async def compute_award(db_award, db_live, tender_id: str, actor_id: str) -> dict:
    """Runs as award_role. Reads only via award.read_after_both_sealed."""
    # 1. Pull both envelopes (only succeeds if both are sealed)
    rows = await db_award.fetch(
        "SELECT * FROM award.read_after_both_sealed($1)", tender_id)
    if not rows:
        raise RuntimeError("no bidders found")

    # 2. Pull config
    cfg = await db_live.fetchrow(
        "SELECT formula, params, frozen_at FROM award.config WHERE tender_id = $1",
        tender_id)
    if not cfg:
        raise RuntimeError(f"award.config missing for tender {tender_id}")
    if not cfg["frozen_at"]:
        raise RuntimeError("award.config not frozen — cannot compute award")

    # 3. Compute
    packages = [dict(r) for r in rows]
    formula = FORMULAS[cfg["formula"]]
    results = formula(packages, cfg["params"] or {})

    # 4. Sort and identify winner(s) — ties are a legal question, flag them
    eligible = [r for r in results if r.rank is not None]
    eligible.sort(key=lambda r: r.rank)
    winners = [r for r in eligible if r.rank == 1]

    # 5. Build the report
    report = {
        "tender_id": tender_id,
        "computed_at": datetime.now(timezone.utc).isoformat(),
        "actor": actor_id,
        "formula": cfg["formula"],
        "params": cfg["params"],
        "bidders": [
            {
                "bidder_id": r.bidder_id,
                "bidder_name": r.bidder_name,
                "passed_gates": r.passed_gates,
                "ineligible_reason": r.ineligible_reason,
                "compliance_summary": r.compliance_summary,
                "technical_score": str(r.technical_score),
                "evaluated_price": str(r.evaluated_price) if r.evaluated_price else None,
                "fee_score": str(r.fee_score) if r.fee_score else None,
                "final_score": str(r.final_score) if r.final_score else None,
                "rank": r.rank,
            }
            for r in results
        ],
        "winners": [w.bidder_id for w in winners],
        "tie": len(winners) > 1,
        "unranked": [r.bidder_id for r in results if r.rank is None],
    }

    # 6. Hash and persist
    report_bytes = json.dumps(report, sort_keys=True, separators=(",", ":")).encode()
    report_hash = hashlib.sha256(report_bytes).hexdigest()

    async with db_award.transaction() as tx:
        run_id = await tx.fetchval("""
            INSERT INTO award.runs
              (tender_id, formula, params, report, report_hash, actor)
            VALUES ($1,$2,$3::jsonb,$4::jsonb,$5,$6)
            RETURNING id
        """, tender_id, cfg["formula"], json.dumps(cfg["params"], default=_jsonable),
             json.dumps(report, default=_jsonable), report_hash, actor_id)
        await append_audit(tx, tender_id, None, actor_id, "award_compute",
                           "award.runs", run_id, None,
                           {"report_hash": report_hash,
                            "winner": report["winners"][0] if len(winners) == 1 else None,
                            "tie": report["tie"]})

    return {"run_id": str(run_id), "report_hash": report_hash, "report": report}

award.runs is append-only (same trigger pattern as audit.ledger). Every recomputation produces a new row; the current award is "the latest run". You can always show the history.

# audit/checkpoint.py — runs as a CronJob every hour
async def create_checkpoint(tender_id: str):
    head = await db.fetchrow("""
        SELECT id, hash, (SELECT COUNT(*) FROM audit.ledger WHERE tender_id = $1)
               AS n
        FROM audit.ledger
        WHERE tender_id = $1
        ORDER BY ts DESC, id DESC LIMIT 1
    """, tender_id)
    if not head:
        return None
    prev = await db.fetchval("""
        SELECT id FROM audit.checkpoints WHERE tender_id = $1
        ORDER BY created_at DESC LIMIT 1
    """, tender_id)
    now = datetime.now(timezone.utc).isoformat()
    message = f"{tender_id}|{head['hash']}|{head['n']}|{now}".encode()
    sig = await kms.sign(settings.SEAL_KEY_ID, message)
    return await db.fetchval("""
        INSERT INTO audit.checkpoints
          (tender_id, head_id, head_hash, entry_count,
           signature, signer_key_id, prev_checkpoint_id, created_at)
        VALUES ($1,$2,$3,$4,$5,$6,$7,$8)
        RETURNING id
    """, tender_id, head["id"], head["hash"], head["n"],
         base64.b64encode(sig).decode(), settings.SEAL_KEY_ID, prev, now)

B.2 WORM export (nightly)

Each nightly export produces an immutable bundle in S3 with Object Lock in COMPLIANCE mode — even root cannot delete it before the retention period ends. The bundle includes the ledger entries since the last export, the checkpoint covering them, and the seal snapshots.

# audit/export.py — runs as a CronJob nightly at 02:00 UTC
import gzip, json, hashlib
from pathlib import Path

def merkle_root_over_hashes(hashes: list[str]) -> str:
    if not hashes: return hashlib.sha256(b"").hexdigest()
    layer = hashes
    while len(layer) > 1:
        nxt = []
        for i in range(0, len(layer), 2):
            a = layer[i]
            b = layer[i+1] if i+1 < len(layer) else a
            nxt.append(hashlib.sha256((a+b).encode()).hexdigest())
        layer = nxt
    return layer[0]

async def export_tender(tender_id: str, out_dir: Path):
    out_dir.mkdir(parents=True, exist_ok=True)

    # 1. Entries since the last export
    last = await db.fetchrow("""
        SELECT max(created_at) FROM audit.exports WHERE tender_id = $1
    """, tender_id)
    since = last["max"] if last and last["max"] else "1970-01-01"

    rows = await db.fetch("""
        SELECT id::text, ts, tender_id::text, envelope, actor::text,
               action, target_table, target_id::text,
               before, after, prev_hash, hash
        FROM audit.ledger
        WHERE tender_id = $1 AND ts > $2
        ORDER BY ts, id
    """, tender_id, since)

    if not rows:
        return None

    # 2. Write NDJSON (gzipped, deterministic)
    ndjson_path = out_dir / "ledger.ndjson.gz"
    with gzip.open(ndjson_path, "wt", encoding="utf-8", mtime=0) as f:
        for r in rows:
            entry = {k: (r[k].isoformat() if hasattr(r[k], "isoformat") else r[k])
                     for k in r.keys()}
            f.write(json.dumps(entry, sort_keys=True, separators=(",", ":")) + "\n")

    # 3. Merkle root over entry hashes (the entries carry their own prev_hash chain)
    root = merkle_root_over_hashes([r["hash"] for r in rows])

    # 4. Seal snapshots (publicly verifiable)
    seals = await db.fetch("""
        SELECT tender_id::text, envelope, merkle_root, leaf_count, snapshot,
               signature, signer_key_id, signed_at::text, prev_seal_id::text,
               revoked_at::text, revoke_reason
        FROM technical.seals WHERE tender_id = $1
        UNION ALL
        SELECT tender_id::text, envelope, merkle_root, leaf_count, snapshot,
               signature, signer_key_id, signed_at::text, prev_seal_id::text,
               revoked_at::text, revoke_reason
        FROM commercial.seals WHERE tender_id = $1
        ORDER BY signed_at
    """, tender_id)
    seals_path = out_dir / "seals.json"
    seals_path.write_text(json.dumps(
        [dict(r) for r in seals], sort_keys=True, indent=2, default=str))

    # 5. Checkpoint covering this export
    ckpt = await db.fetchrow("""
        SELECT id::text, created_at::text, head_id::text, head_hash,
               entry_count, signature, signer_key_id, prev_checkpoint_id::text
        FROM audit.checkpoints WHERE tender_id = $1
        ORDER BY created_at DESC LIMIT 1
    """, tender_id)

    # 6. Manifest — signed, chained to previous manifest
    prev_manifest_path = out_dir.parent / "MANIFEST.json"
    prev_manifest_sha = None
    if prev_manifest_path.exists():
        prev_manifest_sha = hashlib.sha256(prev_manifest_path.read_bytes()).hexdigest()

    manifest = {
        "version": 1,
        "tender_id": tender_id,
        "period": {
            "from": rows[0]["ts"].isoformat(),
            "to": rows[-1]["ts"].isoformat(),
        },
        "entry_count": len(rows),
        "first_entry_hash": rows[0]["hash"],
        "last_entry_hash": rows[-1]["hash"],
        "first_entry_prev_hash": rows[0]["prev_hash"],
        "merkle_root": root,
        "checkpoint": dict(ckpt) if ckpt else None,
        "seal_merkle_roots": [
            {"envelope": s["envelope"], "merkle_root": s["merkle_root"],
             "leaf_count": s["leaf_count"], "signature": s["signature"],
             "signer_key_id": s["signer_key_id"]}
            for s in seals
        ],
        "previous_manifest_sha256": prev_manifest_sha,
        "exported_at": datetime.now(timezone.utc).isoformat(),
    }

    # 7. Sign the manifest with the KMS
    manifest_bytes = json.dumps(manifest, sort_keys=True, separators=(",", ":")).encode()
    manifest_sig = await kms.sign(settings.SEAL_KEY_ID, manifest_bytes)
    manifest["signature"] = base64.b64encode(manifest_sig).decode()
    manifest["signer_key_id"] = settings.SEAL_KEY_ID

    manifest_path.write_text(json.dumps(manifest, sort_keys=True, indent=2))
    manifest_sha = hashlib.sha256(manifest_path.read_bytes()).hexdigest()

    # 8. Upload to WORM bucket (Object Lock, COMPLIANCE mode, 7-year retention)
    prefix = f"audit/{tender_id}/{rows[-1]['ts'].date().isoformat()}"
    for local, name in [(ndjson_path, "ledger.ndjson.gz"),
                        (seals_path, "seals.json"),
                        (manifest_path, "MANIFEST.json")]:
        await s3.put_object(
            Bucket=settings.WORM_BUCKET,
            Key=f"{prefix}/{name}",
            Body=local.read_bytes(),
            ObjectLockMode="COMPLIANCE",
            ObjectLockRetainUntilDate=datetime.now(timezone.utc) + timedelta(days=365*7),
            ChecksumAlgorithm="SHA256",
        )

    # 9. Record the export in the live DB (for incremental since-last-export)
    async with db.transaction() as tx:
        await tx.execute("""
            INSERT INTO audit.exports
              (tender_id, period_to, entry_count, merkle_root, manifest_sha,
               s3_prefix, signature)
            VALUES ($1,$2,$3,$4,$5,$6,$7)
        """, tender_id, rows[-1]["ts"], len(rows), root, manifest_sha,
             prefix, manifest["signature"])

    # 10. Publish the manifest hash to the external anchor (see B.7)
    await anchor.publish(tender_id, manifest_sha, manifest["merkle_root"])

    return {"prefix": prefix, "manifest_sha": manifest_sha}

B.4 Offline verifier CLI

This is the artifact you hand to an external auditor. It has no network calls, no DB access, and no dependency on your infrastructure. Only Python stdlib + cryptography.
python

#!/usr/bin/env python3
# tools/verify_audit.py
"""Offline audit verifier.

Usage:
    verify_audit.py --bundle /path/to/audit/<tender>/ --pubkey seal.pub.pem
                    [--format text|json]

Bundle layout:
    audit/<tender>/
        2026-04-01/
            ledger.ndjson.gz
            seals.json
            MANIFEST.json
        2026-04-02/
            ...
"""
import argparse, base64, gzip, hashlib, json, sys
from pathlib import Path
from dataclasses import dataclass, field
from datetime import datetime
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey
from cryptography.hazmat.primitives import serialization

GENESIS = "0" * 64

@dataclass
class VerifyResult:
    ok: bool = True
    errors: list[str] = field(default_factory=list)
    warnings: list[str] = field(default_factory=list)
    stats: dict = field(default_factory=dict)

    def fail(self, msg: str):
        self.ok = False
        self.errors.append(msg)

    def warn(self, msg: str):
        self.warnings.append(msg)

def sha256(b: bytes) -> str:
    return hashlib.sha256(b).hexdigest()

def canonical_manifest_bytes(manifest: dict) -> bytes:
    m = {k: v for k, v in manifest.items() if k not in ("signature", "signer_key_id")}
    return json.dumps(m, sort_keys=True, separators=(",", ":")).encode()

def verify_manifest_signature(manifest: dict, pubkey: Ed25519PublicKey, res: VerifyResult):
    if "signature" not in manifest:
        res.fail("manifest missing signature")
        return
    try:
        pubkey.verify(base64.b64decode(manifest["signature"]),
                      canonical_manifest_bytes(manifest))
    except Exception as e:
        res.fail(f"manifest signature invalid: {e}")

def recompute_entry_hash(entry: dict) -> str:
    payload = {
        "tender_id": entry["tender_id"],
        "envelope": entry.get("envelope"),
        "actor": entry.get("actor"),
        "action": entry["action"],
        "target_table": entry.get("target_table"),
        "target_id": entry.get("target_id"),
        "before": entry.get("before"),
        "after": entry.get("after"),
        "prev_hash": entry["prev_hash"],
    }
    return sha256(json.dumps(payload, sort_keys=True,
                             separators=(",", ":"),
                             default=str).encode())

def merkle_root(hashes: list[str]) -> str:
    if not hashes: return sha256(b"")
    layer = list(hashes)
    while len(layer) > 1:
        nxt = [sha256((layer[i] + layer[i+1] if i+1 < len(layer) else layer[i]+layer[i]).encode())
               for i in range(0, len(layer), 2)]
        layer = nxt
    return layer[0]

def verify_chain(entries: list[dict], expected_first_prev: str, res: VerifyResult):
    prev = expected_first_prev
    for i, e in enumerate(entries):
        if e["prev_hash"] != prev:
            res.fail(f"entry {i} ({e['id']}): prev_hash mismatch "
                     f"(expected {prev[:12]}…, got {e['prev_hash'][:12]}…)")
            return
        if recompute_entry_hash(e) != e["hash"]:
            res.fail(f"entry {i} ({e['id']}): recomputed hash mismatch")
            return
        prev = e["hash"]

def verify_manifest(manifest_path: Path, pubkey: Ed25519PublicKey,
                    res: VerifyResult) -> dict | None:
    manifest = json.loads(manifest_path.read_text())
    verify_manifest_signature(manifest, pubkey, res)
    if not res.ok:
        return None

    # ledger
    ndjson_path = manifest_path.parent / "ledger.ndjson.gz"
    entries = []
    with gzip.open(ndjson_path, "rt", encoding="utf-8") as f:
        for line in f:
            entries.append(json.loads(line))

    if len(entries) != manifest["entry_count"]:
        res.fail(f"entry_count mismatch: manifest={manifest['entry_count']}, "
                 f"file={len(entries)}")
    if entries[0]["hash"] != manifest["first_entry_hash"]:
        res.fail("first_entry_hash mismatch")
    if entries[-1]["hash"] != manifest["last_entry_hash"]:
        res.fail("last_entry_hash mismatch")
    if entries[0]["prev_hash"] != manifest["first_entry_prev_hash"]:
        res.fail("first_entry_prev_hash mismatch")

    verify_chain(entries, manifest["first_entry_prev_hash"], res)

    root = merkle_root([e["hash"] for e in entries])
    if root != manifest["merkle_root"]:
        res.fail(f"merkle_root mismatch: recomputed {root[:12]}…, "
                 f"manifest {manifest['merkle_root'][:12]}…")

    # seals
    seals = json.loads((manifest_path.parent / "seals.json").read_text())
    for s_meta in manifest["seal_merkle_roots"]:
        matching = [s for s in seals
                    if s["envelope"] == s_meta["envelope"]
                    and s["merkle_root"] == s_meta["merkle_root"]]
        if not matching:
            res.fail(f"seal {s_meta['envelope']}: no matching seal record")
            continue
        # verify the seal signature itself
        try:
            msg = (f"{matching[0]['tender_id']}|{matching[0]['envelope']}|"
                   f"{matching[0]['merkle_root']}|{matching[0]['leaf_count']}|"
                   f"{matching[0]['prev_seal_id'] or ''}").encode()
            pubkey.verify(base64.b64decode(matching[0]["signature"]), msg)
        except Exception as e:
            res.fail(f"seal {s_meta['envelope']}: signature invalid: {e}")

    return manifest

def verify_bundle(bundle_dir: Path, pubkey: Ed25519PublicKey,
                  res: VerifyResult) -> None:
    manifests = sorted(bundle_dir.glob("*/MANIFEST.json"))
    if not manifests:
        res.fail(f"no MANIFEST.json found under {bundle_dir}")
        return

    prev_sha = None
    for mp in manifests:
        m = verify_manifest(mp, pubkey, res)
        if m is None:
            res.fail(f"{mp.parent.name}: manifest verification failed, stopping")
            return
        if m.get("previous_manifest_sha256") != prev_sha:
            res.fail(f"{mp.parent.name}: previous_manifest_sha256 mismatch "
                     f"(expected {prev_sha}, got {m.get('previous_manifest_sha256')})")
            return
        prev_sha = sha256(mp.read_bytes())

    res.stats["manifests"] = len(manifests)
    res.stats["last_manifest_sha"] = prev_sha

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--bundle", required=True, type=Path)
    ap.add_argument("--pubkey", required=True, type=Path)
    ap.add_argument("--format", choices=["text", "json"], default="text")
    args = ap.parse_args()

    pub = serialization.load_pem_public_key(args.pubkey.read_bytes())
    if not isinstance(pub, Ed25519PublicKey):
        print("public key must be Ed25519", file=sys.stderr)
        sys.exit(2)

    res = VerifyResult()
    verify_bundle(args.bundle, pub, res)

    if args.format == "json":
        print(json.dumps({"ok": res.ok, "errors": res.errors,
                          "warnings": res.warnings, "stats": res.stats},
                         indent=2))
    else:
        print(f"Bundle: {args.bundle}")
        print(f"Result: {'PASS' if res.ok else 'FAIL'}")
        for k, v in res.stats.items():
            print(f"  {k}: {v}")
        for e in res.errors:
            print(f"  ERROR: {e}")
        for w in res.warnings:
            print(f"  WARN:  {w}")

    sys.exit(0 if res.ok else 1)

if __name__ == "__main__":
    main()

Failure modes the verifier catches:

    Any ledger entry modified (hash mismatch at that entry).

    Any ledger entry deleted (chain break at next entry's prev_hash).

    Entries reordered (prev_hash mismatch).

    Manifest tampering (signature fails).

    Manifest deleted (chain skips a previous_manifest_sha256).

    Seal snapshot tampered (seal signature fails).

    Seal record inserted post-hoc (not in manifest's seal_merkle_roots).

    Wrong public key (all signatures fail — clearly identifies the cause).

B.5 Recovery tool (witness DB)

If the live database is lost or suspect, reconstruct the full ledger state into a read-only witness database from the exported bundle alone.
python

# tools/replay_ledger.py
"""Reconstruct audit state from exported bundle into a fresh Postgres DB."""
import gzip, json, argparse
from pathlib import Path
import psycopg

def replay(bundle_dir: Path, dsn: str):
    manifests = sorted(bundle_dir.glob("*/MANIFEST.json"))
    with psycopg.connect(dsn) as conn:
        with conn.cursor() as cur:
            cur.execute("""
                CREATE TABLE IF NOT EXISTS audit_witness.ledger (
                    id UUID, ts TIMESTAMPTZ, tender_id UUID, envelope TEXT,
                    actor UUID, action TEXT, target_table TEXT, target_id UUID,
                    before JSONB, after JSONB, prev_hash TEXT, hash TEXT,
                    PRIMARY KEY (hash)
                );
                CREATE INDEX IF NOT EXISTS ON audit_witness.ledger (tender_id, ts);
            """)
            # load in manifest order
            for mp in manifests:
                with gzip.open(mp.parent / "ledger.ndjson.gz", "rt") as f:
                    for line in f:
                        e = json.loads(line)
                        cur.execute("""
                            INSERT INTO audit_witness.ledger VALUES
                              (%(id)s,%(ts)s,%(tender_id)s,%(envelope)s,%(actor)s,
                               %(action)s,%(target_table)s,%(target_id)s,
                               %(before)s,%(after)s,%(prev_hash)s,%(hash)s)
                            ON CONFLICT (hash) DO NOTHING
                        """, e)
        conn.commit()

B.7 Publishing keys and roots

Trust depends on the verifier having a public key they can trust. Options, in increasing strength:

    Publish the public key on your tender portal, alongside the audit bundle. Auditors cross-check against a second source (e.g. a government procurement portal).

    RFC 3161 timestamping: submit each manifest hash to a public timestamping authority. The returned token is stored in the bundle. Verifies the manifest existed at that moment.

    Transparency log (Certificate Transparency style): publish each manifest's merkle root to an append-only public log with an inclusion proof. This is the strongest option — it makes the published history globally verifiable, not just trust-me-verify-locally.

    Newspaper / public notice (still surprisingly strong): publish monthly merkle roots in a public register. Cost-free and tamper-evident.

At minimum, do (1) and (2). For any procurement likely to be challenged or litigated, do (3).

The pubkey rotation story matters too: keys are versioned (signer_key_id is stored alongside every signature), the archive of seal-YYYY.pub.pem files is retained forever, and the KMS enforces a minimum retention so old keys can't be deleted.

A.1 Threat model

Every cryptographic control is only as good as the key that operates it. Be explicit about what you're defending against:
Threat	Attacker capability	Defence
Compromised API server	Full read/write on app layer	Key never on app box; HSM-held
Malicious DBA	Full DB read/write	Key not derivable from DB; seals are cryptographic
Malicious insider (lead/procurement)	Correct role, ill intent	Separation of duty + quorum + audit
Malicious admin	Can deploy code, change RBAC	Admin has no HSM access; key policy forbids

Coercion	Attacker physically forces signer	Duress code + quorum (can't be coerced alone)

Key compromise (undetected)	Signing arbitrary content	Anomaly detection; short key lifetime; root signing

Two structural responses address most of these: keys in an HSM (not on any server) and quorum for high-stakes operations (seal + unseal).
A.2 Key hierarchy

Three tiers. Each tier's compromise has different blast radius:

            │
            │ signs

            │
            │ signs
            ▼
   SEALS / CHECKPOINTS / MANIFESTS

   ANCHOR KEY                     (separate service, publishes)

Key	Custody	Quorum	Rotation	Blast radius if lost

Seal	Online HSM (AWS CloudHSM, Azure Managed HSM, or a YubiHSM plugged into the seal worker)	2-of-3 for high-value tenders; otherwise approval workflow	12 months	New seals impossible until root re-signs; existing seals verifiable
Anchor	Same HSM as seal key (separate key slot) or an isolated signing service	1-of-1 (low-value), 2-of-3 for politically sensitive	12 months	Anchor fails, but manifest still timestamped by RFC 3161

The root key is the trust anchor. It never signs tender content — it only signs "this seal key is authorised for period T". This means an attacker who compromises the online seal key cannot forge historical seals (the root pubkey archives prove what keys were valid when). They can only produce future seals, and those are detectable because the root didn't authorise the compromise key.

Store the root pubkey in three places: the operational archive, a government register, and a physical safe in a different building.

A.4 The seal signing flow — an approval workflow, not a function call

The seal_envelope function from the earlier build was a single API call. In production it becomes a multi-step ceremony with human approval and a signed challenge:
text

1. Lead initiates seal → creates a pending_approval record (no signature yet)
2. System constructs a SIGNING CHALLENGE containing:
     - Tender reference + envelope name
     - Merkle root of the snapshot
     - Leaf count
     - Snapshot hash (SHA-256 of the full snapshot JSON)
     - Coverage statistics (unreviewed=0, needs_clarification=0)
     - Timestamp
3. Challenge is displayed to the lead for review (large, human-readable)
4. Lead approves → request routed to the HSM
5. HSM signs the EXACT challenge → returns signature
6. System verifies the returned signature against the challenge + the CURRENT seal pubkey
7. Signature + snapshot stored in `seals` table
8. Audit entry written with full challenge + response

The key property: the HSM signs a challenge, not the snapshot directly. The challenge includes the snapshot hash, so the signed artefact commits to the exact content. Any attempt to substitute the snapshot after signing fails verification.

    # AWS KMS: sign with an asymmetric Ed25519 key
    resp = await kms_client.sign(
        KeyId=settings.SEAL_KEY_ARN,
        Message=ch.canonical(),
        MessageType="RAW",
        SigningAlgorithm="ECDSA_SHA_256",  # or ED25519 if KMS supports

A.5 Quorum unseal ceremony — the specific ask

Unsealing is the highest-stakes operation in the system. It happens after a correction is genuinely needed (bidder withdrew, evaluator error found, court order). The quorum makes it impossible for one person to unseal.

Recommended threshold: 2-of-3 for most tenders, 3-of-5 for tenders above a threshold (say S$50m contract value, or any tender currently under challenge). The number should be in the tender's award.config metadata.
The two technical approaches

Option 1 — Shamir's Secret Sharing (simpler, air-gapped). The unseal private key is split into 5 shares; any 3 combine to reconstruct it. Each executive holds one share on a YubiKey (the share is encrypted to a PIN the executive alone knows). To unseal: three executives meet, each inserts their YubiKey and enters their PIN, the shares are combined in an air-gapped laptop's memory, the reconstructed key signs the unseal authorisation, and the key is wiped.

Option 2 — Threshold Ed25519 (FROST, no reconstruction). The private key never exists in one place at any time. Three executives participate in a distributed signing protocol; each contributes a signature fragment; the fragments combine into one valid Ed25519 signature. The private key is mathematically never reassembled.

For most deployments, FROST is the right answer. It removes the "reconstruction window" attack — even the three cooperating executives cannot extract the key, they can only produce one signature for one message. The infrastructure is more complex, but the security property is cleaner.

    participants: [{name, role, email, yubikey_serial}]
    threshold: e.g. 3 for 3-of-5

        # nowhere in the live system

        "max_signers": len(participants),
        "participants": shares,

def executive_contribute(share_file: str, yubikey_pin: str,
                         unseal_challenge: bytes) -> dict:
    """Run by each executive independently. Produces one signing fragment."""
    share = decrypt_from_yubikey(share_file, yubikey_pin)
    signing_ceremony = SigningCeremony(
        message=unseal_challenge,
        key_package=share,
        # coordinator sends commitments from other participants
        signer_commitments=[],  # populated by coordinator
    )
    commitment = signing_ceremony.commit()
    return {"participant_id": share.identifier, "commitment": commitment}

def coordinator_finalize(fragments: list[dict], unseal_challenge: bytes,
                         group_pub, threshold: int) -> bytes:
    """Run by the coordinator after collecting >= threshold fragments."""
    if len(fragments) < threshold:
        raise RuntimeError(f"need {threshold} fragments, got {len(fragments)}")
    sig = SigningCeremony.aggregate(
        message=unseal_challenge,
        signer_commitments=fragments,
        public_key_package=group_pub,
    )
    # verify against the group pubkey before returning
    if not verify_signature(sig, unseal_challenge, group_pub):
        raise RuntimeError("threshold signature failed verification")
    return sig

The physical ceremony protocol

For any unseal of a tender above the threshold, the ceremony is:

    Notice (T-48h): the requesting lead files a written unseal request. The procurement officer acknowledges.

    Assembly: at least threshold executives physically convene in a room with a notary and a witness (not one of the signers).

    Air-gapped laptop: powered on, network disabled, from a locked case. Runs the ceremony tool.

    Each executive connects their YubiKey, enters their PIN, produces one signature fragment.

    Coordinator (one of the signers, or the notary) collects fragments and produces the aggregated signature.

    Everyone verifies: the signature verifies against the published group pubkey, the message is the intended unseal authorisation.

    Notarisation: the notary records the ceremony — participants, time, place, authorisation content, resulting signature. This record goes into the audit ledger as a scanned document.

    Submission: the unseal authorisation is submitted to the API. The API verifies the threshold signature, logs it, and processes the unseal.

    Recording: audio/video of the ceremony is retained (per jurisdictional requirements — in Singapore, typically 7 years for procurement).

# app/sealing/rotate.py — run in a planned change window
async def rotate_seal_key(new_key_arn: str, run_by: str):
    """
    Order of operations is critical:
    1. Generate new key in HSM
    2. ROOT SIGNS the transition statement (old_key_id -> new_key_id, valid_from)
    3. Transition statement is published (portal + gazette + archive)
    4. New seals start using new key; old key retained but never used again
    5. Pubkey published
    """
    now = datetime.now(timezone.utc).isoformat()
    old_key_id = settings.SEAL_KEY_ID

    transition = {
        "tender_id": "*",  # applies globally
        "action": "seal_key_transition",
        "from_key_id": old_key_id,
        "to_key_id": new_key_arn,
        "valid_from": now,
        "reason": "scheduled_annual_rotation",
    }
    transition_bytes = json.dumps(transition, sort_keys=True,
                                  separators=(",", ":")).encode()

    # ROOT KEY signs the transition — this is the only way new seal keys
    # become trusted. The root ceremony happens here, quorum required.
    root_sig = await root_quorum_sign(transition_bytes)

    # Verify the transition before deploying
    if not verify_root_signature(root_sig, transition_bytes,
                                  await load_root_pubkey()):
        raise RuntimeError("root signature failed verification — aborting")

    # Store transition (append-only)
    async with db.transaction() as tx:
        await tx.execute("""
            INSERT INTO technical.key_transitions
              (from_key_id, to_key_id, valid_from, transition, root_sig, run_by)
            VALUES ($1, $2, $3, $4::jsonb, $5, $6)
        """, old_key_id, new_key_arn, now,
             json.dumps(transition), root_sig, run_by)
        await append_audit(tx, "*", None, run_by, "seal_key_rotation",
                           "technical.key_transitions", None, None, transition)

    # Update config (new deployment picks this up)
    await notify_operations(f"Seal key rotating from {old_key_id} to {new_key_arn}")

The verification uses the archived pubkey (permanently retained) that corresponds to old_key_id, plus the root-signed transition proving old_key_id was valid when the seal was created:

async def verify_seal_across_rotations(seal: dict) -> bool:
    # 1. Load the pubkey for the key that signed this seal
    pub = await load_archived_pubkey(seal["signer_key_id"])
    if pub is None:
        return False
    # 2. Verify the seal's signature
    if not verify_seal_signature(seal, pub):
        return False
    # 3. Verify the key was valid at the seal's signed_at
    transition = await db.fetchrow("""
        SELECT * FROM technical.key_transitions
        WHERE to_key_id = $1 AND valid_from <= $2
        ORDER BY valid_from DESC LIMIT 1
    """, seal["signer_key_id"], seal["signed_at"])

        transition["root_sig"], transition["transition"].encode(),
        await load_root_pubkey()):

    return True

A.7 Compromise detection and response

Detecting a compromised seal key:

    Anomaly alerts: any seal audit entry outside the lead's normal hours, any seal not preceded by a matching create_seal_challenge within 20 minutes, any seal on a tender the lead is not assigned to.

    Signature audit: weekly job re-verifies all seals signed in the last 30 days against the archived pubkeys. Failures indicate either tampering or key compromise.

    Public anchor drift: if the transparency log shows entries the internal ledger doesn't, or vice versa — investigate immediately.

Response playbook if the seal key is compromised:

    Contain: disable the KMS key (requires IAM change + witness). All signing stops.

    Assess scope: query the ledger for all signatures produced by the key in the suspected window. The signer_key_id + hash chain tells you exactly what was signed and when.

    Rotate: invoke the root ceremony to sign a compromise declaration + a new seal key. The declaration is published alongside the rotation.

    Re-seal where necessary: any sealed envelope whose seal is within the compromise window is suspect. The ledger shows whether the recorded snapshot matches what the seal committed to — if it does, the seal is fine (the key was used legitimately at that time). If not, unseal + re-seal with fresh content.

    Notify: publication to the government register + affected bidders. This is not optional — undetected compromise that becomes public later is far worse.

    Root key compromise (worst case): all seal keys are presumed compromised. Full re-establishment, every active tender re-verified against the WORM archive, public disclosure.

The reason this is survivable is that the WORM archive + the transparency log give you the ground truth for what was actually signed, independent of what the live system says. Even a compromised key can't retroactively change what the anchor recorded.
A.8 Anti-rubber-stamp controls

The single most common failure mode in practice is not cryptographic — it's a human approving 30 seals in five minutes because the UI makes it easy. Control it:

    Challenge rendering is mandatory: the signer must see the full challenge (tender reference, merkle root, leaf count, snapshot hash) rendered as text, not just a "Sign" button. No bulk-sign endpoint.

    Rate limit: 3 seals per tender per 24 hours. More than that is a symptom of a broken process.

    Physical witness for high-value: tenders above the value threshold require a second FIDO2 key (the procurement officer) to be present at signing, so two humans are in the room.

    Time-of-day alerts: seals outside 08:00–20:00 SGT generate an alert (may be legitimate, but never silently). Over time, track the alert-to-seal ratio — if it stays at 0, the alerts are being ignored.

    Duress code: the signer can enter a special PIN that produces a valid-looking signature but silently triggers an alert and a rate limit. This protects against coercion without alerting the coercer.

    Retroactive review: monthly, a sample of seals is re-reviewed by a separate evaluator (not the lead who sealed). This is the only way to catch "signed correctly but the underlying scores were wrong."

Part B — The anchor
B.1 What the anchor protects against

Everything in Parts 1–A protects against attackers tampering within your system. The anchor protects against you — including your admins, your DBA, your HSM compromise scenario. It answers one question:

    "Was this manifest published at this time, and has it been modified since?"

The answer must come from a party other than you. Ideally several.

The trust model with an anchor:

    The manifest is a signed commitment to a merkle root (all history up to time T).

    The anchor proves: this manifest hash existed at time T, witnessed by [party].

    After the anchor, no one — including you — can produce a different manifest with the same hash-and-time pair without detection.

    So: any retroactive rewrite of the ledger requires either (a) breaking cryptography, or (b) rewriting the anchor's records. Neither is possible for a public transparency log.

B.2 Layered strategy

Don't rely on a single anchor. Use three, at different strengths and cost profiles:
Layer	Provider	Cost	Guarantee	Availability dependency
1. RFC 3161 timestamp	Sectigo / DigiStamp / GlobalSign	~$0.10–1 per stamp	This hash existed at this time	The TSA's continued validity (they typically outlast your tender)
2. Public transparency log	Sigstore Rekor (free, public) or self-hosted Trillian	Free / low	Global append-only public record; inclusion proof	Sigstore's continued availability (mitigated by mirroring)
3. Bitcoin attestation	OpenTimestamps	~$0 per stamp	This hash existed before block N; cannot be rewritten without forking Bitcoin	Bitcoin's continued existence (extremely high)

Layered means: layer 1 alone is fine for routine, layer 1+2 for high-value, layer 1+2+3 for anything likely to be challenged. Cost increases are small; the defence is multiplicative.

def verify_timestamp(manifest_bytes: bytes, tsr: dict) -> dict:
    from rfc3161ng import RemoteTimestamper
    from asn1crypto import tsp, cms
    token = tsp.TimeStampResp.load(base64.b64decode(tsr["token_der"]))
    status = token["status"]["status"].native
    if status != "granted":
        return {"ok": False, "reason": f"status={status}"}
    tst_info = token["time_stamp_token"]["content"]["encap_content_info"]["content"]
    # verify the message hash matches
    if tst_info["message_imprint"]["hashed_message"].native != \
       hashlib.sha256(manifest_bytes).digest():
        return {"ok": False, "reason": "hash mismatch"}
    gen_time = tst_info["gen_time"].native  # the timestamp
    return {"ok": True, "timestamp": gen_time.isoformat(),
            "tsa": tst_info.get("tsa", "unknown")}

B.4 Layer 2 — Transparency log (Sigstore Rekor)

Rekor is a public append-only log with merkle inclusion proofs. Submitting the manifest hash creates a globally visible, immutable record.
python

# anchor/rekor.py
import requests, hashlib, base64

async def anchor_to_rekor(manifest_bytes: bytes, manifest: dict) -> dict:
    """Submit the manifest hash to the public Sigstore Rekor log."""
    digest = hashlib.sha256(manifest_bytes).hexdigest()

    # Construct a Rekor entry — a "hashedrekord" of type sha256
    entry = {
        "apiVersion": "0.0.1",
        "kind": "hashedrekord",
        "spec": {
            "data": {"hash": {"algorithm": "sha256", "value": digest}},
            "signature": {
                "content": base64.b64encode(
                    (await kms.sign(settings.ANCHOR_KEY_ID,
                                    manifest_bytes))).decode(),
                "publicKey": {"content": base64.b64encode(
                    (await kms.get_public_key(settings.ANCHOR_KEY_ID))
                    .public_bytes_pem()).decode()},
            },
        },
    }
    r = requests.post("https://rekor.sigstore.dev/api/v1/log/entries",
                      json=entry, timeout=30)
    r.raise_for_status()
    resp = r.json()
    entry_uuid = next(iter(resp.keys()))
    log_index = resp[entry_uuid]["logIndex"]
    inclusion_proof = resp[entry_uuid]["verification"]["inclusionProof"]

    return {
        "type": "rekor",
        "log_url": "https://rekor.sigstore.dev",
        "entry_uuid": entry_uuid,
        "log_index": log_index,
        "inclusion_proof": inclusion_proof,
    }

def verify_rekor_inclusion(manifest_bytes: bytes, proof: dict) -> dict:
    """
    Verify the manifest is included in the Rekor log.
    Uses the log's signed tree head + inclusion proof — offline, no network call.
    """
    from sigstore_rekor_verify import verify_inclusion
    result = verify_inclusion(
        entry_uuid=proof["entry_uuid"],
        log_index=proof["log_index"],
        inclusion_proof=proof["inclusion_proof"],
        log_pubkey_pem=proof["log_public_key"],
    )
    return {
        "ok": result.valid,
        "signed_entry_timestamp": result.signed_entry_timestamp,
    }

The property: the Rekor log is public, independently monitored (by Sigstore's operators and by community transparency monitors), and any modification would be detected globally. Even if you wanted to rewrite history, you can't — the entries are in the log.
B.5 Layer 3 — OpenTimestamps (Bitcoin)

For long-term durability, anchor the manifest hash into the Bitcoin blockchain. It's free, permanent, and the security rests on Bitcoin's proof-of-work.
python

# anchor/opentimestamps.py
import subprocess, tempfile, os

async def anchor_to_bitcoin(manifest_bytes: bytes) -> dict:
    with tempfile.TemporaryDirectory() as d:
        manifest_path = os.path.join(d, "MANIFEST.json")
        ots_path = manifest_path + ".ots"
        with open(manifest_path, "wb") as f:
            f.write(manifest_bytes)
        # ots-cli submits the hash to calendar servers
        subprocess.run(["ots", "stamp", manifest_path], check=True, timeout=60)
        with open(ots_path, "rb") as f:
            ots_proof = f.read()
    return {
        "type": "opentimestamps",
        "proof_bytes": base64.b64encode(ots_proof).decode(),
        "status": "pending",  # becomes "confirmed" after ~1 hour (next block)
    }

def verify_ots(manifest_bytes: bytes, proof: dict) -> dict:
    with tempfile.TemporaryDirectory() as d:
        manifest_path = os.path.join(d, "MANIFEST.json")
        ots_path = manifest_path + ".ots"
        with open(manifest_path, "wb") as f:
            f.write(manifest_bytes)
        with open(ots_path, "wb") as f:
            f.write(base64.b64decode(proof["proof_bytes"]))
        result = subprocess.run(
            ["ots", "verify", manifest_path],
            capture_output=True, text=True, timeout=120)
        return {
            "ok": result.returncode == 0,
            "output": result.stdout,
        }

A.5.1 Seal re-verification (30-day window)
python

# ops/weekly/reverify_seals.py — cron, Monday 10:00 SGT
async def reverify_recent_seals(days=30):
    seals = await db.fetch("""
        SELECT s.id, s.tender_id, s.envelope, s.merkle_root, s.leaf_count,
               s.snapshot, s.signature, s.signer_key_id, s.signed_at,
               s.prev_seal_id
        FROM technical.seals s
        WHERE s.signed_at > now() - interval '%s days'
          AND s.revoked_at IS NULL
        UNION ALL
        SELECT s.id, s.tender_id, s.envelope, s.merkle_root, s.leaf_count,
               s.snapshot, s.signature, s.signer_key_id, s.signed_at,
               s.prev_seal_id
        FROM commercial.seals s
        WHERE s.signed_at > now() - interval '%s days'
          AND s.revoked_at IS NULL
    """ % (days, days))
    failures = []
    for seal in seals:
        pub = await load_archived_pubkey(seal["signer_key_id"])
        snapshot = seal["snapshot"]
        leaves = [canonical_row(r) for r in _flatten_for_merkle(snapshot)]
        if merkle_root(leaves) != seal["merkle_root"]:
            failures.append((seal["id"], "merkle mismatch"))
            continue
        msg = f"{seal['tender_id']}|{seal['envelope']}|{seal['merkle_root']}|" \
              f"{seal['leaf_count']}|{seal['prev_seal_id'] or ''}".encode()
        try:
            pub.verify(base64.b64decode(seal["signature"]), msg)
        except Exception as e:
            failures.append((seal["id"], f"signature: {e}"))
    if failures:
        await escalate_p1("seal re-verification failures", failures)
    return {"checked": len(seals), "failed": len(failures)}

Any failure is a P1. A signature failure on a 30-day-old seal means either the seal was tampered with, or the archived pubkey is wrong, or the signing ceremony was compromised. None of these are minor.

python

def sample_seals(month: str, n: int = 5) -> list[str]:
    seed = int(hashlib.sha256(f"{month}-seal-sample".encode()).hexdigest()[:8], 16)
    rng = random.Random(seed)
    sealed = [s["id"] for s in query(
        f"SELECT id FROM technical.seals WHERE signed_at LIKE '{month}%' "
        f"AND revoked_at IS NULL")]
    return rng.sample(sealed, min(n, len(sealed)))

Seeded sampling is important — an auditor asked to sample might subconsciously pick "safe" tenders. The seed is fixed at the start of the month (published in the ops log) and the resulting sample is what gets reviewed.

A.9 Incident response

Every incident follows a numbered procedure. The procedures share a preamble:

    Classify severity (P1–P4 per table below)

    Notify the escalation chain (§A.9.5)

    Contain using the procedure's specific containment steps

    Preserve evidence — do not restart services, do not delete logs, do not modify anything until the incident is documented

    Resolve — follow the resolution steps

    Post-mortem within 5 business days (P1/P2) or 10 business days (P3/P4)

Severity	Definition	Response time	Escalation
P1	Chain integrity failure, seal verification failure, unauthorized envelope access, key compromise suspected	Immediate page	System owner + CIO
P2	Anchor unavailable >24h, WORM export failure, RBAC misconfiguration	1 hour	System owner
P3	Individual tool failure (verifier bug, UI issue), single-tender anomaly	Same business day	Operations lead
P4	Cosmetic, non-blocking, "nice to fix"	Next sprint	Team lead
A.9.1 Chain integrity failure (P1)

Symptom: audit.verify_chain() returns ok=false for any tender, OR weekly seal re-verification fails.

Immediate actions (within 15 minutes):

    Do not attempt to fix anything. The chain is broken. Modifying it makes it worse.

    Screenshot the failure: which entry ID, which tender, which field.

    Export the current state: pg_dump --schema=audit > /tmp/incident-<timestamp>.sql

    Snapshot the WORM archive for that tender: aws s3 sync s3://audit-worm-prod/audit/<tender>/ /tmp/incident-<timestamp>-worm/

    Notify the system owner + CIO.

    Freeze the tender: mark it under_review (a new state) so no additional actions are taken on it.

    Notify the procurement officer and the affected bidders (via the tender's communication channel) — §A.9.1 note below.

Investigation:

    Run compare_chain_heads.py between the live DB and the WORM archive for that tender.

    The first divergent entry identifies the moment of tampering.

    Query the ledger around that entry: which actions were logged immediately before and after? Which users?

    Pull application logs from the API for the 24 hours around the divergence — which authenticated sessions wrote at that time?

    Pull DB access logs (assuming you have pgAudit configured) — which DB roles executed UPDATE/DELETE on audit.ledger? (This should be nothing — the trigger blocks it — which means either a trigger bypass or a superuser.)

Resolution paths:

    Path A — accidental corruption (rare; usually a deployment bug that wrote to audit.ledger in a way that bypassed the trigger): restore from the WORM archive, document the bug, fix the bug, re-run verify.

    Path B — DB role privilege issue: revoke the privilege, restore from WORM, audit what else that role did.

    Path C — malicious tampering: this is now a criminal matter. Preserve everything. Engage forensics. Do not resolve the incident technically until investigation concludes. The procurement officer decides how to handle the tender — legal advice is required.

Note on bidder notification: whether to notify bidders that a chain integrity failure occurred is a legal/procurement decision, not a technical one. The default in Singapore public sector is disclosure, and delayed disclosure is usually worse than early disclosure — if the tampering affected their tender, they need to know. But the decision sits with the procurement officer + legal, not the ops team.
A.9.2 Seal verification failure (P1)

Symptom: weekly re-verification fails for one or more seals.

Same as §9.1, plus:

    Check the archived pubkey used for verification — is it the correct one for that signer_key_id? A pubkey mismatch produces a false failure.

    Check the seal's snapshot field — is it intact?

    Cross-reference against the WORM archive — does the archive contain the same seal?

    If the failure is confirmed: freeze the affected tender, treat as §9.1.

A.9.3 Anchor reconciliation failure (P2)

Symptom: manifests are not found in Rekor/TSA/OTS, or reconciliation shows mismatch.

Actions:

    For a single missing manifest: check the anchor submission API logs — did the anchor call succeed? If not, re-submit the same manifest.

    Do not re-create or modify the manifest — re-submit the same file. Only the anchor re-submission is safe.

    If re-submission succeeds → incident is P3 (process gap). Post-mortem: how did the anchor failure go undetected?

    If re-submission fails → the anchor itself is having issues (§7.2) or the manifest content is disputed. Escalate to P1.

If the anchor refuses to accept a manifest that your live system has already sealed against, you have a serious problem. The manifest is the external commitment to what the ledger contained; if the anchor says "no", the anchor is your ground truth, not the live system.
A.9.4 Unauthorized envelope access (P1)

Symptom: alert fires — e.g. a commercial evaluator's session viewed a technical row, or a lead viewed commercial before technical was sealed, or admin hit an envelope endpoint.

Actions:

    Immediately revoke the session token: UPDATE core.users SET session_revoked_at=now() WHERE id=<user> (the API checks this on every request).

    Preserve the audit log for the user's session.

    Query what the session saw: SELECT * FROM audit.ledger WHERE actor=<user> AND ts > <session start> ORDER BY ts.

    Assess: was data actually returned, or was the attempt blocked? (Check the API access log — a 403 in the log means the attempt was blocked; a 200 with envelope data in the response body means it was not.)

    If data was returned: the seal on the accessed envelope is compromised until proven otherwise. Freeze the tender. This is where the "the seal on the technical envelope is a commitment to the state of knowledge" matters — if a commercial evaluator saw technical scores before commercial scoring, the commercial evaluation is tainted.

    Notify procurement officer + legal. Investigate the mechanism: was this a policy gap, a bug, or a deliberate attack?

    Remedy path: unseal + re-score + re-seal, with the affected party excluded, is often required. This is expensive but necessary.

A.9.5 Quorum unavailability during an incident (P2 → escalated by context)

Symptom: You need to unseal or rotate, and enough unseal quorum members are unavailable (travel, illness, departed the org) to reach the threshold.

Immediate actions:

    Contact the designated deputies — every quorum member has a deputy from the A.2 table. Deputies hold duplicate shares.

    If deputies are also unavailable, this becomes a governance problem, not a technical one. The procurement officer + legal + CIO make the call about whether to delay, or to invoke an emergency quorum procedure.

    Emergency quorum procedure (documented in the runbook, requires CIO approval): a temporary quorum of 2 named executives can substitute for one unavailable member, with both signing together (so 3-of-5 still holds with the two substitutes counting as one). This is a one-time-per-incident exception, logged as a special audit entry with the CIO's approval on file.

The emergency procedure exists because real life happens. It must be pre-documented, pre-approved, and pre-distributed to quorum members and their deputies, so it can be invoked without scrambling.

A.10 Key ceremonies

These are the highest-stakes manual procedures. Every ceremony has:

    A checklist PDF printed and physically present

    Two witnesses (one a notary for ceremonies above the value threshold)

    Video recording retained per retention policy (Singapore: typically 7 years for procurement)

    Written record signed by every participant, scanned, and archived in WORM

A.10.1 Seal signing ceremony (routine)

Routine sealing happens via approval workflow — the "ceremony" is small:

    Lead initiates seal in the UI → challenge rendered on screen

    Lead reads the challenge carefully (this takes 60 seconds; rate limit prevents rushing)

    Lead clicks "Approve" → challenge goes to the seal worker → KMS signs

    Worker verifies the returned signature against the challenge + current seal pubkey

    Signature recorded, audit entry written

For routine tenders, no physical ceremony is required. The rate limit (3 seals/tender/24h) and the mandatory challenge display are the controls.
A.10.2 High-value seal signing (physical)

For tenders above the value threshold:

    Assemble: lead + procurement officer + witness (not one of the two)

    Air-gapped device: the seal challenge is rendered on a laptop not connected to the network, pulled from a signed QR code generated by the API

    Read aloud: the lead reads the challenge parameters aloud (tender ref, envelope, leaf count, merkle root, snapshot hash)

    Procurement officer confirms: co-signs by entering their FIDO2 PIN

    Witness confirms: signs the paper checklist

    Return: the two signatures are transcribed onto the API's signing endpoint (via a one-time challenge ID)

    Verify: the API verifies both signatures against the challenge, then signs via KMS

    Record: checklist + video + challenge → WORM

The "read aloud" step is intentional — it makes rubber-stamping harder. A physical human reading a merkle root aloud is unlikely to skip the review.
A.10.3 Unseal ceremony (physical, quorum)

This is the most formal. Protocol per §A.5 of the previous message, expanded:

48 hours before:

    Written unseal request from evaluation lead

    Acknowledged by procurement officer

    Notary + witness confirmed

    Quorum members confirmed (at least threshold, prefer threshold+1)

    Air-gapped laptop prepared: charged, OS updated, FROST tool installed and hash-verified against the published binary hash

Day of ceremony:

    Seal the room (physical): phones in a Faraday bag, door closed, witness confirms no one leaves

    Read the request aloud: reason, tender, envelope, authorisation chain

    Power on air-gapped laptop — network disabled verified (not just toggled off — the witness confirms no wifi/ethernet indicator)

    Each quorum member in turn:

        Insert YubiKey

        Enter PIN (on the laptop, not on the YubiKey — never type PIN into anything except the ceremony tool)

        Produce commitment + share fragment

    Coordinator (one of the quorum or the notary) aggregates the fragments once threshold is reached

    Verify the resulting threshold signature against the published group pubkey

    Wipe the laptop memory: sudo shutdown -h now, remove battery if possible, then the device is stored in a tamper-evident bag until the next ceremony

    Sign the paper checklist: every participant signs, notary signs, witness signs

    Capture the result: the unseal authorisation (the signed message) is transcribed via QR code into the API

    Submit the unseal via API — this triggers the actual unseal workflow

    Video + checklist + authorisation → WORM archive

Failure modes handled:

    A quorum member's YubiKey fails → they are replaced by a deputy, ceremony continues from the current point (deputies must also be present or reachable; hence "prefer threshold+1")

    The air-gapped laptop crashes → wipe and restart; the ceremony is idempotent (each participant can re-produce their fragment for the same message)

    The message changes after some participants have signed → STOP. Any change requires re-running the ceremony from step 1. The nonce prevents a partial signature from one ceremony being used for another.

    A participant suspects coercion → duress code produces a valid-looking fragment but the resulting aggregate signature will fail verification at the API (which the user is told will happen, but which looks like success to the coercer). Also triggers a silent alert.

A.10.4 Seal key rotation ceremony

Per §10.6 of the previous message. Add the physical ceremony steps:

    Root HSM retrieval: two of the root key quorum open the safe together (in Singapore: a bank vault under dual custody)

    Air-gapped root machine: an offline laptop in the vault room, with the FROST root signing tool

    Root quorum signs: the 3-of-5 root quorum produces the transition signature

    Return root HSM: two-person verification of the safe re-sealing

    Deploy transition: the root-signed transition is entered into the operations system, which verifies it and updates the current seal key

    Publish: the transition + new seal pubkey are published to the tender portal, government register, and (via anchor) the transparency log

The root key ceremony is annually rehearsed (§8.2) — the dress rehearsal for the root ceremony is not optional; a root ceremony failing under duress is a catastrophic event.
A.10.5 Disaster recovery

Three scenarios, three procedures. Each is tested quarterly, on staging.
DR-1: Live database lost

Scenario: the production Postgres is destroyed (disk failure, region outage, accidental DROP).

Recovery:

    Restore from the most recent Postgres snapshot (RPO: ≤15 minutes with streaming replica lag).

    Verify chain from snapshot: SELECT audit.verify_chain(...) for each tender.

    Compare snapshot to WORM archive for the last export: does the restore match? (Should — WORM has more recent data than the snapshot.)

    Replay from WORM: replay_ledger.py to bring the audit ledger up to the most recent WORM export.

    Verify again: chain intact, all seals verifiable against archived pubkeys.

    If the restore cannot be made consistent with WORM: the WORM archive is now the primary record. The live system becomes a read-only witness DB until the discrepancy is understood. Bidders are notified per §A.9.1.

RTO: 2 hours for the DB restore, 4 hours to verify and return to service.
DR-2: Seal HSM unavailable

Scenario: the HSM (AWS CloudHSM cluster) is unavailable — AWS outage, network partition, cluster failure.

Recovery:

    No new seals can be created until the HSM recovers. Do not bypass with a software key — that defeats the entire model.

    Notify: any seal scheduled in the next 24 hours is deferred.

    AWS CloudHSM has HA (2+ instances in different AZs) — a single instance failure is transparent. A cluster-wide failure is a serious AWS event; follow AWS status.

    If the HSM is lost or corrupted: restore from the HSM backup (AWS CloudHSM supports backup and restore; the backup is encrypted and requires two backup keys to restore — those are held by two security officers separately).

    If the backup cannot be restored: the seal key is lost. The rotation procedure (via root key) establishes a new seal key. Existing seals are still verifiable against archived pubkeys — that's the point of archiving them. The only damage is "cannot create new seals until rotation."

RTO: 4 hours (single-instance) to 2 days (worst-case rotation).
DR-3: Anchor provider permanently down

Scenario: Sigstore Rekor is shut down; Sectigo discontinues its TSA; OTS calendar servers stop.

Recovery:

    Switch to the next provider in the anchor strategy — the layered design exists for this.

    Verify: for existing manifests, do you have enough archived proof to verify them after the provider is gone?

        RFC 3161: yes, if the TSA certificate chain is archived. The timestamp token doesn't require the TSA to be online for verification — it only requires the trust anchor.

        Rekor: yes, if the inclusion proof + log pubkey are archived. The proof is verifiable offline.

        OTS: yes, the proof is self-contained; Bitcoin provides the trust.

    New anchors: submit to a new provider (a second TSA for RFC 3161, a self-hosted Trillian for transparency log, etc.). Update the runbook and the verifier to accept the new provider's proofs.

RTO: Immediate — you can keep operating with the archived proofs; the anchor policy for future manifests is a policy decision that can be made over days.

The key realisation for DR-3: the anchor's job is done once you have the proof in hand. Losing the provider doesn't lose the anchors already published — it only affects new ones. This is what makes the layered strategy resilient.

Part B — FROST DKG ceremony

The trusted-dealer setup in the previous message is the pragmatic first step. For a system that expects to be challenged, DKG removes a trust assumption the trusted dealer creates: that one machine, at one moment, held the full unseal key.

DKG replaces it with a protocol where the key never exists in one place at any moment. Each participant holds a share from the beginning; the group public key is derived from everyone's contributions.
B.1 Why bother — what the trusted dealer costs you

The trusted-dealer setup for the unseal quorum:

    Runs on a machine the team controls

    Generates the full group private key in memory

    Splits it via Shamir / FROST trusted-dealer keygen

    Distributes shares

    Zeroises the master key

Even done well, this creates three risks:
Risk	What the attacker gets	Mitigated by DKG?
Compromise of the setup machine during setup	Full unseal key — can unseal any tender forever	✅ Yes — the key never exists on that machine
Compromise of the setup operator (insider threat)	Possibility of embedding a backdoor share	✅ Yes — every participant verifies their share
Supply chain attack on the setup tool	Full unseal key	✅ Yes — each participant independently verifies the transcript
Coercion of the setup operator	Full key, with plausible deniability (they say they zeroised it)	✅ Yes — there's no moment where coercion works

DKG removes these, at the cost of a more involved ceremony (~90 minutes vs ~20) and a stricter set of participant requirements.
B.2 FROST DKG protocol — what actually happens

FROST uses a variant of Pedersen's DKG with the FROST secret sharing scheme. The protocol has two rounds, plus a finalisation. All communication is authenticated (each message is signed by the participant's identity key).

Setup:

    n participants (5), threshold t (3)

    Each participant has an Ed25519 identity key (their signing key, not the quorum key) — used to authenticate DKG messages

    Each participant has a commitment nonce — a one-time random value used to bind their contributions

Round 1 — commit:
Each participant i:

    Generates a random polynomial f_i(x) of degree t-1, with f_i(0) as their secret contribution

    Generates a random polynomial g_i(x) of degree t-1 (used for Feldman VSS — verifying shares without revealing them)

    Broadcasts commitments to the coefficients of both polynomials:

        C_i[k] = g^(a_{i,k}) for k=0..t-1 (coefficients of f_i)

        D_i[k] = g^(b_{i,k}) for k=0..t-1 (coefficients of g_i)

    Also broadcasts a proof of knowledge (Schnorr NIZK) that they know f_i(0)

Round 2 — share:
Each participant i, for each other participant j:

    Computes s_{i,j} = f_i(j) and s'_{i,j} = g_i(j)

    Encrypts (s_{i,j}, s'_{i,j}) to participant j's public key

    Sends the encrypted share to j

Each recipient j:

    Decrypts all received shares

    Verifies each share s_{i,j} against the commitments from i:
    g^(s_{i,j}) == ∏ (C_i[k]^(j^k)) — Feldman VSS check

    Verifies s'_{i,j} against D_i similarly

    If all shares verify: accepts

    If any share fails: broadcasts a complaint against participant i

Finalisation:
Each participant j:

    Computes their final share: x_j = Σ_i s_{i,j} (over all accepted i)

    Computes their final verification share: Y_j = Σ_i s'_{i,j}

    The group public key: Y = ∏_i C_i[0] = ∏_i g^(a_{i,0}) = g^(Σ_i a_{i,0})

    Publicly verifies: g^(x_j) == Y_j — confirms their share is consistent with the group key

The result: The group secret key sk = Σ_i a_{i,0}. No participant ever knows sk. Each participant j knows only x_j, their share. Any t participants can collaborate (via the FROST signing protocol) to produce a signature without reconstructing sk.
B.3 Using the FROST-DKG library

The reference implementation is the Rust frost-ed25519 crate (Zcash Foundation) — has frost-dkg support. Python bindings exist but are young; for a serious deployment, use the Rust crate directly via a Rust ceremony tool, or wrap with PyO3.

For this build, I'll write the ceremony orchestration in Python and call the Rust tool as a subprocess. This is more honest than pretending Python does the crypto.

B.5 The ceremony — step by step
B.5.1 Opening (15 minutes)

    Coordinator opens the ceremony: reads the purpose, the threshold, the participant list.

    Notary confirms the identities of all present.

    Each participant:

        Reads aloud their name and participant ID

        Shows their YubiKey's serial number — matches the pre-registered serial

        Confirms they have the ceremony tool and its hash matches the published one

    IT support confirms each laptop's network is disabled, wifi off, bluetooth off.

    Coordinator reads the ceremony tool version and hash aloud; every participant confirms they see the same.

    Video starts. Everything from here is recorded.

B.5.2 Round 1 — commitments (20 minutes)

Each participant, in turn:

    Inserts their YubiKey

    Runs:
    bash

    frost-dkg round1 \
      --participant-id "${PID}" \
      --threshold 3 \
      --max-signers 5 \
      --output round1-${PID}.json \
      --identity-key /path/to/yubikey

    The tool prompts for the YubiKey PIN — entered on the participant's laptop keyboard only

    The tool produces round1-${PID}.json — their commitments

    Participant reads the hash aloud:
    bash

    sha256sum round1-${PID}.json

    The coordinator records the hash in the paper transcript

    Participant copies their file to a USB stick (the one designated for ceremony transfer — it's clean and formatted)

    IT support collects the USB sticks and transfers all files to the coordinator's machine via the local switch

Coordinator:
bash

frost-dkg coordinator round1-merge \
  --inputs round1-*.json \
  --output round1-all.json

Reads the hash of round1-all.json aloud. Every participant verifies the hash matches by independently computing it from their own copy.

If any hash mismatches → STOP. A mismatch means the message was tampered with in transit. Restart from the beginning of Round 1.
B.5.3 Round 2 — shares (30 minutes)

Each participant:

    Runs:
    bash

    frost-dkg round2 \
      --round1-all round1-all.json \
      --participant-id "${PID}" \
      --output round2-${PID}-to-*.json \
      --identity-key /path/to/yubikey

    The tool produces one file per recipient (round2-${PID}-to-1.json, ..., round2-${PID}-to-5.json)

    Important: each file is encrypted to the recipient's public key — participants cannot read each other's shares

    Participant reads the hash of each output file aloud as it's produced

    Notary records all hashes in the transcript

    Files are transferred to the coordinator via the local switch (same process as Round 1)

Coordinator:

    Routes files to each recipient (each participant receives their own round2-*-to-${PID}.json files)

    Each participant verifies each received share:
    bash

    frost-dkg round2-verify \
      --shares round2-*-to-${PID}.json \
      --round1-all round1-all.json \
      --output round2-${PID}-verified.json

    If verification fails: participant announces a complaint against the sender:
    bash

    frost-dkg round2-complain \
      --against-participant "${BAD_PID}" \
      --round2-share round2-${BAD_PID}-to-${PID}.json \
      --output complaint-${PID}.json

    Any complaint must be resolved before proceeding — the DKG is restarted for that participant, or the participant is removed and the quorum is re-run (if the removed participant's removal still meets the threshold).

Every participant reads aloud "verified" or "complaint" — the notary records each.
B.5.4 Finalisation (15 minutes)

Each participant:

    Runs:
    bash

    frost-dkg finalize \
      --round1-all round1-all.json \
      --round2-verified round2-${PID}-verified.json \
      --participant-id "${PID}" \
      --output participant-${PID}-share.json

    The output contains:

        Their secret share (encrypted to their YubiKey)

        Their verification share Y_j

        The group public key Y

    Participant reads the group public key hash aloud

    Every participant confirms the same hash — a mismatch means the group key is not consistent across participants, and the ceremony is invalid

Coordinator:
bash

frost-dkg verify-group \
  --participant-shares participant-*.json \
  --expected-threshold 3

Reads the result aloud: "Group key verified, threshold 3-of-5."
B.5.5 Post-ceremony (10 minutes)

    Each participant stores their participant-${PID}-share.json to their YubiKey:
    bash

    frost-dkg store-share --share participant-${PID}-share.json --yubikey-slot 9c

    The share is now inside the YubiKey, encrypted. The plaintext file is deleted.

    Wipe each participant's laptop:
    bash

    shred -vfz -n 7 participant-*.json round1-*.json round2-*.json

    IT support confirms all devices are wiped

    Security officer confirms all YubiKeys are accounted for

    Coordinator records the group public key in the ceremony transcript:
    text

    Group public key: 5f3a2e8b1c9d4a7e6b2f8c...
    SHA-256: 7c1d4e...

    Notary stamps and signs the paper transcript. Every participant signs.

    Video recording stopped, labelled, and archived.

B.5.6 Announcement

The group public key is published:

    On the tender portal's verification page

    In the government register

    To the transparency log (as a special entry with the ceremony transcript hash)

Anyone can now verify future unseal signatures against this key. The key's identity is established by the ceremony.
B.6 The ceremony tool — implementation

The Rust frost-dkg CLI is the safest choice. Here's the Python orchestration that wraps it and manages the ceremony state, transcripts, and records.
python

# tools/frost_ceremony.py — the coordinator's tool
import subprocess, json, hashlib, os
from pathlib import Path
from dataclasses import dataclass, asdict
from datetime import datetime, timezone

CEREMONY_TOOL = "/usr/local/bin/frost-dkg"  # hash-verified at start

@dataclass
class CeremonyState:
    ceremony_id: str
    threshold: int
    max_signers: int
    participants: list[str]          # participant IDs, e.g. ["P1", "P2", "P3", "P4", "P5"]
    round1_hashes: dict[str, str]    # participant -> hash
    round1_all_hash: str = ""
    round2_hashes: dict[str, dict[str, str]] = {}  # sender -> recipient -> hash
    complaints: list[dict] = None
    group_pubkey: str = ""
    status: str = "initialised"

    def __post_init__(self):
        if self.complaints is None:
            self.complaints = []

    def save(self, path: Path):
        path.write_text(json.dumps(asdict(self), indent=2, default=str))

# ── Setup ──────────────────────────────────────────────────────────────────

def init_ceremony(threshold: int, max_signers: int,
                  participants: list[str]) -> CeremonyState:
    if len(participants) != max_signers:
        raise ValueError("participants count must equal max_signers")
    if not (2 <= threshold <= max_signers):
        raise ValueError("threshold must be 2..max_signers")
    return CeremonyState(
        ceremony_id=f"dkg-{datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%SZ')}",
        threshold=threshold, max_signers=max_signers,
        participants=participants,
    )

# ── Round 1: collect commitments from participants ──────────────────────────

def collect_round1(state: CeremonyState, incoming_dir: Path, out: Path):
    """Called by coordinator after participants place their round1 files."""
    for pid in state.participants:
        f = incoming_dir / f"round1-{pid}.json"
        if not f.exists():
            raise RuntimeError(f"missing round1 from {pid}")
        h = hashlib.sha256(f.read_bytes()).hexdigest()
        state.round1_hashes[pid] = h

    # Verify all hashes against what was read aloud in the room
    for pid, expected in state.round1_hashes.items():
        read_aloud = input(f"Paste read-aloud hash for {pid} (or 'skip'): ").strip()
        if read_aloud and read_aloud != expected:
            raise RuntimeError(f"hash mismatch for {pid}: {read_aloud} != {expected}")

    # Merge via the ceremony tool
    inputs = [str(incoming_dir / f"round1-{pid}.json") for pid in state.participants]
    r = subprocess.run(
        [CEREMONY_TOOL, "coordinator", "round1-merge",
         "--inputs", *inputs, "--output", str(out / "round1-all.json")],
        capture_output=True, text=True, check=True,
    )
    state.round1_all_hash = hashlib.sha256((out / "round1-all.json").read_bytes()).hexdigest()
    state.status = "round1-complete"
    return r.stdout

# ── Round 2: route shares ───────────────────────────────────────────────────

def route_round2(state: CeremonyState, incoming_dir: Path, out: Path):
    """Called after participants place their round2 output files."""
    by_recipient = {pid: [] for pid in state.participants}

    for sender in state.participants:
        state.round2_hashes[sender] = {}
        for recipient in state.participants:
            f = incoming_dir / f"round2-{sender}-to-{recipient}.json"
            if not f.exists():
                state.complaints.append({"from": recipient, "against": sender,
                                          "reason": "missing"})
                continue
            state.round2_hashes[sender][recipient] = hashlib.sha256(f.read_bytes()).hexdigest()
            by_recipient[recipient].append(f)

    # Route to each recipient
    for recipient, files in by_recipient.items():
        dest = out / "routed" / recipient
        dest.mkdir(parents=True, exist_ok=True)
        for f in files:
            (dest / f.name).write_bytes(f.read_bytes())

    if state.complaints:
        state.status = "round2-complaints"
    else:
        state.status = "round2-routed"
    return by_recipient

# ── Finalise ───────────────────────────────────────────────────────────────

def finalise(state: CeremonyState, incoming_dir: Path, out: Path):
    """Called after participants place their finalised share files."""
    if state.complaints:
        raise RuntimeError("unresolved complaints — cannot finalise")

    shares = []
    group_keys = set()
    for pid in state.participants:
        f = incoming_dir / f"participant-{pid}-share.json"
        if not f.exists():
            raise RuntimeError(f"missing finalised share from {pid}")
        share = json.loads(f.read_text())
        shares.append(str(f))
        group_keys.add(share["group_public_key"])

    if len(group_keys) != 1:
        raise RuntimeError(
            f"group public key mismatch across participants: {group_keys}"
        )
    state.group_pubkey = group_keys.pop()

    # Verify via ceremony tool
    r = subprocess.run(
        [CEREMONY_TOOL, "verify-group",
         "--participant-shares", *shares,
         "--expected-threshold", str(state.threshold)],
        capture_output=True, text=True, check=True,
    )
    state.status = "complete"
    return r.stdout

B.7 Deputies and share rotation

Every quorum member has a deputy (per A.2). The deputy has their own YubiKey with a duplicate of the member's share. How is the deputy's YubiKey provisioned without re-running the whole ceremony?

Two options:

Option A — duplicate at ceremony time (simpler, slightly weaker): before the ceremony ends, the participant writes their share to two YubiKeys (their primary and the deputy's), both in the presence of the notary. The ceremony log records both serial numbers. The deputy's YubiKey is sealed in tamper-evident packaging and held by the security officer until needed.

Option B — share rotation (stronger, more complex): after the ceremony, the participant runs a share refresh protocol with their deputy — this is a two-party protocol that produces a new share for the deputy without revealing the original. Both shares still work in the FROST aggregation (they're shares of the same group secret). This uses Proactive Secret Sharing (PSS).

For Singapore public sector construction tenders, Option A is typically accepted, provided that the deputy's YubiKey is held by a different security officer than the member's. That is, the deputy can't access their share without involving another officer, which means the deputy is not a "soft" single point of failure.

For a stronger requirement (e.g. high-value tenders), Option B is recommended. The library support exists (frost-dkg has a share refresh mode) but the ceremony is more involved; budget 2 hours per rotation.

Share rotation schedule: same as key rotation — annually, with the seal key rotation. Do them in the same ceremony window. This limits the number of "all quorum must be present" events per year and makes the scheduling predictable.
